## Q1 · 他给的公司**未披露口径**的外部估算是什么？

本件是一份无署名中文汇编，通篇没有一处「某券商/某分析师」的出处。它给了一整套 Meta 未披露的单位经济估算，全部标外部估算：

① 单用户周成本：重度用户（把每周 1 亿 token 额度用满）约 80 美元/周，对应月成本接近 300 美元；普通免费用户因虚拟机多处于空闲，月成本约 60–100 美元。期间是 2026 年 9 月的产品状态，样本量未给（是单个用户还是一批用户的均值，不明）。
② 成本参数：对外 API 标价输入 1.25 美元/百万 token、输出 4.25 美元/百万 token；Meta 真实场景输入输出约 3:1；自有算力下内部推理成本约为 API 标价的 30%；云端虚拟机每周 15–20 美元。四个参数里只有前两个是可查的公开价，后两个是估算。
③ 变现参照：豆包生态内跳转交易的抽佣「平均约十几个点」，用来给 Meta 的交易抽佣定锚——没有任何来源、没有样本、没有品类拆分。

判断：①有总量、有期间、有代理变量（token 用量 + 虚拟机租金），可以复算（见下题）；②里的「30%」与「3:1」没有推导，只能当量级；③是纯口述锚点，不得入格。按作业规则，本件无署名、无机构、无脚注，全部数字只能当线索，必须另找署名源才能升档。

## Q2 · 他的**物理量**从哪来、能不能核？

无法核。

这份材料里没有任何电力、机柜、GPU 张数、厂房面积、晶圆产能层面的物理量。我逐页查过：产品定位一节只有架构描述，功能与场景一节只有生态清单，横向对比一节只有三家国内产品与 ChatGPT Agent 的架构差异，成本一节只到 token 与虚拟机租金，产业链一节只到板块与标的。全文没有一处 GW、MW、机柜数、卡数。

唯一带物理含义的两个量是：每位用户一台独立的云端安全虚拟机（即并发虚拟机的台数等于活跃用户数，可作容量估算的锚），以及免费版每周 1 亿 token 的额度（可折算成推理负载）。但这两个都只给了口径、没有给用户数，所以折不出任何绝对量级。

判断：这是本件最大的空缺——它谈了一家 agent 产品的单位成本，却不谈这家公司为此要建多少算力。要把它的「80 美元/周」接到 Meta 的资本开支上，至少缺活跃用户数与单虚拟机规格两个输入，材料一个都不给。做产能测算时本件只能提供需求侧假设，不能提供供给侧读数。

## Q4 · 他的**假设与算式**能不能复算？

能复算前两步，第三步缺口径。

它的算式是：周成本 =（输入 token × 输入单价 + 输出 token × 输出单价）× 内部成本折扣 + 虚拟机周租。

复算：免费额度 1 亿 token/周，按 3:1 拆成 7,500 万输入 + 2,500 万输出。按对外 API 价：7,500 万 × 1.25/百万 = 93.75 美元；2,500 万 × 4.25/百万 = 106.25 美元；合计 200 美元/周。乘 30% = 60 美元/周 —— 与材料 Q&A 里的「内部推理成本约每周 60 美元」完全对上，复算通过。再加虚拟机 15–20 美元，得 75–80 美元，与它说的「周成本约 80 美元」相符，第二步也通过。

第三步走不通：月成本。它说「接近 300 美元」。按 4 周算 80×4 = 320，比 300 高 6.7%；按 4.33 周算 346，高 15%。材料没交代一个月按几周折算，也没交代「接近 300」是取整还是另有折扣，所以这一步不能复算，只能记「300 上下」。

判断：这套单位经济模型的前两步是自洽的，可以拿来当 Meta 单用户成本的上限框架（因为它假设额度用满）；但 30% 这个折扣系数没有推导，一旦换成 20% 或 40%，周成本就变成 40–80 美元，结论会翻转。所以能复算的是算术，不能复算的是那个关键假设。

### 依据
- p.2｜b. 重度用户成本：假设 Token 额度用满，叠加虚拟机开销后每周总成本约 80 美元，对应月成本接近 300美元，仅最重度用户会达到该使用强度。
- p.3｜A: 成本主要包括模型推理 TOKEN成本与云端虚拟机开销。
- p.2｜对比当前 20 美元/月、100美元/月两档订阅套餐来看，20美元仅能覆盖轻度用户成本，重度用户成本暂无法被订阅收入完全覆盖，当前存在一定成本端压力。

## Q6 · 他的**自建口径 / 评级**定义是什么？与公司口径差多少？

自建了一把尺子，定义给了一半。

尺子是「内部推理成本 = 对外 API 标价 × 30%」。它把公司对外挂牌价当成成本上限，再用一个折扣系数折成自有算力下的真实成本。这个思路在方法上说得通（对外价含毛利与第三方转售加价），但 30% 这个系数没有推导、没有对照（比如没有拿同行的自建/外售价比做校验），也没有区分 prefill 与 decode。

第二把尺子是「三类产品架构对比」：以「是否给每位用户独立持久虚拟机、能否关掉 APP 后继续跑、能否跨公网」为轴，把 Meta Muse 与微信小微、阿里千问、ChatGPT Agent 分成四类。只有分类规则，没有打分权重，也没有量化。

与公司口径的差：Meta 从不披露单位推理成本，也不披露订阅的用户结构，所以严格说无法与公司口径对照。可对照的只有价格——20 美元/月与 100 美元/月两档，材料自己算出 20 美元档只覆盖轻度用户，重度用户成本覆盖不了。

判断：第一把尺子可以借框架、不能借系数（30% 必须自己重估）；第二把尺子只能当产品分类用，不能当竞争力量化表。它的「算力成本为三类产品最高」这句没有任何量化支撑，属于该口径未定义却已被用来支撑结论。

### 依据
- p.2｜自有算力支撑下内部推理成本约为对外 API标价的 30%
- p.1｜a.底层架构：Meta Muse 配备用户专属独立云端虚拟机，自带完整 Chrome 浏览器，关闭 APP 后后台仍可持续运营
- p.1｜Meta Muse优势是支持后台持续运行、安全性高，劣势是算力成本为三类产品最高，合规成本也较高，国内落地可行性存疑
- p.2｜b. 交易环节抽佣：为中期核心增长点，抽佣面向商家收取

## Q8 · 他的**行业级判断**（产能 · 份额）有数据支撑吗？

没有份额与产能数据，全部是观点。

它下的几个大判断：Meta Muse 是「海外首款以 C 端 AI 助手为核心定位的消费级个人 AI Agent」；它的架构「属于行业重大创新」；它的算力成本是三类产品里最高；豆包生态的交易抽佣「平均约十几个点」；发布后「Meta 股价大涨、谷歌股价下跌」，据此推出传统搜索与信息流的流量入口会被挤压。这些断言里没有一处给市场份额、出货量、用户数、产能或统计年份；「首款」「最高」「重大创新」都是排名性表述而无判据。

唯一带外部参照的是豆包抽佣「十几个点」，但它自己也没说是哪类交易、含不含支付通道费，无法当基准。

判断：这是观点，不是读数。它的依据看起来是产品体验对比与二手市场传闻（股价表现只给了方向，没给幅度与日期区间），属于访谈/观察型判断。可用于理解卖方叙事（市场如何讲 Meta Muse 的故事），不可用于任何份额、产能或利润测算；若要引用「首款 C 端 agent」这类定位，必须另找第三方定义与时间线核对。
