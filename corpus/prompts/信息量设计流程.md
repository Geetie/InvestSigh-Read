# 信息量设计流程 —— 学习 → 提案 → 审批（死命令）

> 目标：以**推断**为锚，反推 34 型 × 每题的信息需求设计。每道题要重新回答三个问题：
> ① 这道题实际要为哪些推断提供信息？② 从专家与该领域投资者的视角看，它应当获取的**最大信息量**有哪些？
> ③ 当前读法离这个最大量差在哪，怎么改？
>
> 本流程由用户逐题审批。**参与提案的 agent 必须先学习，未交学习报告或报告未通过审核，不得提案。**这是死命令，不是建议。

## 一、为什么必须先学习

34 型 × 每题需要庞大且专业的知识，而且**视角比答案更重要**——同一份研报，卖方分析师、行业研究员、宏观策略师看到的增量完全不同。没学过该领域专业框架的 agent 出的提案，只能是"把题干换个说法"的形式游戏。所以学习是提案的准入条件，不是可选准备。

## 二、分工：类级子 agent

七类各领一个 agent（01 监管一手披露、02 业绩与沟通、03 卖方与共识、04 资金与持仓、05 产业链与另类、06 宏观与政策、07 情绪与预期），各负责本类 3–7 型的全部题目。

## 三、学习阶段（提案的准入门禁）

**学习输入**（四样，缺一不可）：

1. **本类全部分册**——读法列、必过项、问句表，逐题读，理解每题现在的构思方式；
2. **本类全部存量实卡与对应原材料**——不是扫标题，是实读：看真实材料长什么样、答案实际写出了什么、哪些信息在材料里存在但没进卡；
3. **该领域的专业框架与视角**——如：01 型要懂 SEC 披露结构与会计基础；03 型要懂卖方研究方法论与三态归位背后的分析框架；07 型要懂市场微观结构与情绪指标体系。产出一份**视角清单**：这个领域的专家看材料时，带着哪些问题、哪些默认假设、哪些"外行看不见"的信息维度；
4. **推断锚**——用户提供的推断清单（或估值模型格），每题的服务对象挂在这上面。

**学习产出**（每类一份《学习报告》，交用户审核）：

- 本类各型的**信息地形**：每题现在实际能得到什么（基于实卡实证）、材料的真实形态；
- **视角清单**：该领域专家的知识框架、默认假设、信息维度；
- **当前读法的信息缺口假设**：哪些题的读法把增量挡在了门外（对照"共同信息集"基准）。

**门禁**：学习报告未经用户审核通过，该 agent 不得产出任何题目草案。

## 四、提案阶段

学习报告通过后，按固定格式逐题出草案：

```
型 / 题号 / 题干
服务的推断：〔挂在推断锚的哪一项〕
最大信息清单：〔从专家视角看，这道题应当获取的全部信息维度〕
当前读法缺口：〔现状 vs 最大清单的差〕
读法修改建议：〔具体到读法列怎么改〕
```

## 五、审批与落地

用户逐题批注。批准的读法修改进分册（问句表），同步跑 `sync-cards` 与 `sync-templates`；重要问域按新读法重跑卡片验证。

## 六、试点

先跑 **02 业绩与沟通** 一个类：学习报告 → 用户审 → 提案 → 用户批 → 落地 → 重跑一卡验证。全流程走通、学习报告质量过关后，再铺开其余六类。
