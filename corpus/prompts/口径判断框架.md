# 口径判断框架 —— 提案（待批）

> 老板需求：像折旧这样需要具体情况具体判断的口径项很多，不能一条规则打天下；
> 要有细致深入的设计，让 agent 具备**具体情况具体判断**的能力。
> 本提案给三样东西：①判断项的分类学（哪些判断项存在）；②标的级**口径账**机制（判定怎么落地与维护）；③判据模板样例（具体判断长什么样）。
> **状态：提案待批。**批准后进入实施（判据模板补全 + 口径账试点 + agent 学习阶段挂接）。

## 一、问题的结构

会计口径的"具体情况具体判断"，本质是**会计判断项**（management estimates & judgments）体系：会计准则本身就充满管理层判断——折旧年限、SBC 计量、减值触发、资本化边界、收入确认……每家公司 10-K 的 Critical Accounting Estimates 章节列的就是这些。同一项判断，在不同资产属性的公司身上正确处理不同（折旧：对重资产的 Meta 云业务是必须计入的真实成本；对轻资产的品牌授权公司影响微小）。

所以解法不是"一条全局规则"，而是三层：

1. **判断项分类学**——先系统盘点有哪些判断项（不是遇到一个处理一个）；
2. **标的级口径账**——每家公司一份政策表，记录该公司每个判断项的处理方式与判定依据（数据化，不是拍脑袋）；
3. **判据模板**——每类判断项给"条件 → 处理"的默认规则，agent 按数据信号套用，套不动才人工判断。

四视角呈现层（有机增长 / 核心经营利润 / 自由现金流 / 披露口径，见写法规范 §口径分层）不变——口径账决定的是**每家公司在各视角里每个调整项适用与否**。

## 二、判断项分类学（五类，提案版）

| 类 | 判断项 | 判断的核心 |
|---|---|---|
| **A 资产成本确认** | 折旧摊销 · 研发/内部开发资本化 · 减值 | 资产强度与业务性质；减值要分"一次性确认"与"连续减值=商业模式问题" |
| **B 收入确认** | 递延收入（bookings vs revenue） · 总收入 vs 净收入（gross/net） · 长期合同完工确认 | 增长该看哪个数；平台公司 gross/net 差异可达数倍 |
| **C 费用计量** | 股权激励 SBC · 重组费 | SBC 是分歧最大项（非现金但真实薪酬成本）；连续重组=结构性 |
| **D 汇总与折算** | 汇率 · 并购并表 · 分部加总与合并 | 有机增长的边界；公司间抵消 |
| **E 非经营** | 投资损益 · 利息 · 一次性税项 · 少数股东损益 | 经营利润线的边界 |

每个判断项配一份**判据模板**（见 §四），模板 = "数据信号 → 条件 → 处理"的默认规则。

## 三、标的级口径账（机制）

每家被追踪的公司一份**口径账**（账本体系新成员，与指引账、我方假设账并列）：

```
# 口径账 · META

资产属性判定：重资产（依据：capex/收入 34%、D&A/经营利润 趋势、AI 数据中心资本开支周期位置）

| 判断项 | 该公司政策 | 依据 |
|---|---|---|
| 折旧摊销 | 计入经营能力判断；FCF 对照必给；写明增长性 capex 占比 | 重资产判定 + 老板指示（新云厂商折旧必须算在内） |
| SBC | 经营利润含 SBC；估值对照另给剔 SBC 数（注明稀释） | 分歧项，两层呈现 |
| 汇率 | 有机增长口径（固定汇率折算） | 标准做法 |
| 非主营投资损益 | 经营利润线看主营；净利线只作对照 | 标准做法 |
| 一次性项目 | 公司调节表核对优先；无调节表自行列项标"自行还原" | 标准做法 |
```

**维护流程**（agent 的决策树）：

1. 处理该公司数字 → 先查该公司口径账；
2. 有该项 → 按已批政策呈现；
3. 无该项 → 按判据模板判定 → **登记口径账**（政策 + 数据依据）→ 卡面呈现；
4. 判定依据变化（资产属性漂移，如轻资产公司大举建厂）→ 更新口径账并注明触发数据；
5. 口径账变更在卡面呈现时标注（"口径账 2026-11 起：折旧计入"）。

## 四、判据模板样例（三个，说明具体判断长什么样）

**样例 1 · 折旧摊销**（资产成本确认类）

- 信号：capex/收入（近三年）、D&A/经营利润、固定资产/总资产
- 判据：
  - capex/收入 ≥ 15% 或 D&A/经营利润 ≥ 20% 且持续 → **重资产**：折旧计入经营能力判断（它是真实现金成本的前置确认）；FCF 对照必给；写明资本开支周期位置与增长性占比；
  - capex/收入 < 5% 且 D&A/经营利润 < 10% → **轻资产**：折旧影响微小，经营利润即可代表，不另还原；
  - 中间带或资产属性漂移中 → 两层都给，标明判断与触发数据。
- 反例警示：AI 数据中心建设期把折旧从利润删掉 → 资本开支前置期利润虚高，掩盖真实投入（Meta 现状即是）。

**样例 2 · SBC**（费用计量类——分歧最大项）

- 两个真值：它是真实薪酬成本（股东视角应计入，否则高估盈利）；它是非现金项（现金视角不存在）。
- 判据：经营能力判断 → 计入（公司拿人才是真花了钱）；现金流判断 → 自动不含（FCF 天然剔它）；估值对照 → 给剔 SBC 数并注明稀释。
- 禁止：只给剔 SBC 的"漂亮数"而不标——那是把薪酬成本藏进稀释。

**样例 3 · 递延收入**（收入确认类）

- 信号：deferred revenue 增速 vs revenue 增速的持续背离
- 判据：订阅/预收模式公司 → bookings（或 deferred 增速）与 revenue **并给**，写明"收入滞后于签单"；
- 一次性大单入递延 → 剔出 bookings 口径并注明。

## 五、与现有机制的关系

- **写法规范 §口径分层**：四视角呈现层不变；口径账决定每家公司各调整项适用与否。规范加一句指针："调整项适用性查该公司口径账"。
- **信息量设计流程**：口径政策是学习报告的必产部分——类级 agent 学习阶段必须盘点本类标的的主要判断项，产出口径账初稿（与视角清单并列）。
- **check**：一期不机查（判断项靠知识不靠正则）；二期可查"口径账存在的标的，其经营数字是否引用了账上政策"。

## 六、实施分阶段

1. **判据模板补全**（本提案批准后）：五类约 15–20 项判据模板成文，先覆盖 01/02/03 类高频项；
2. **口径账试点**：META + 1–2 家对照公司（一家重资产、一家轻资产）建账，验证判据模板的可执行性；
3. **学习阶段挂接**：02 类试点（已批准的流程）的学习报告加入口径账初稿；
4. **铺开**：随信息量设计流程逐类推进。
