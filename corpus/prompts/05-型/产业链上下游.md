## 一、六层骨架（AI 算力从硅到电）

行业里对 AI 硬件的分层有多种切法（五层、六层、十一层都有），差异主要在"芯片设计与 EDA 是否合并""整机与互联是否合并"。
本类统一用**六层**，理由是每一层对应一组不同的供应商、一组不同的可测量、一种不同的瓶颈形态。

| 层 | 名称 | 这一层做什么 | 输入 → 输出 | 可测量（主） | 瓶颈形态 |
|---|---|---|---|---|---|
| L0 | 需求 | 云厂商与主权 AI 的算力采购 | 资本开支预算 → 订单 | capex、机柜订单、MW 交付计划 | 预算与电力配额 |
| L1 | 芯片设计 | 加速器与存储的架构设计、EDA/IP | 架构 + 制程 PDK → 流片 | 出货颗数、单卡 HBM 容量、TDP | 设计定档与良率爬坡 |
| L2 | 制造 | 晶圆代工、设备、材料 | 硅片 + 光罩 → 晶圆 | 片/月、制程占比、设备出货额 | 先进制程产能与设备交期 |
| L3 | 封装与存储 | 先进封装、HBM、载板、PCB/CCL | 晶圆 + 存储堆叠 + 基板 → 封装好的加速器模组 | 片/月（CoWoS）、位元、$/Gb、层数 | 先进封装产能（当前主瓶颈） |
| L4 | 整机与互联 | 服务器 ODM、交换、光模块、铜连接、电源、液冷 | 模组 + 网络件 + 电源冷却 → 机柜 | 柜数、端口/模块只数、kW/柜 | 光模块与电源交付 |
| L5 | 数据中心 | 土地、并网、变电、冷却、EPC | MW 配额 + 设备 → 可上电的机房 | MW 交付、PUE、并网排队 | 电力接入与变压器交期 |
| L6 | 云与应用 | 云份额、模型训练推理、终端用量 | 算力 → token / 收入 | 云份额、token 用量、ARPU | 需求端回报率 |

**建构件的第一条判据**：这份材料覆盖的是哪一层？
覆盖多层就**分层建档**，禁一张表混层——混层的典型症状是"把 CoWoS 的片/月和 HBM 的位元放进同一列比较"。

## 二、环节边界：怎么判断"这是不是同一个环节"

同一层里有多个环节，边界靠**输入→输出**判定，不靠名字。

| 层 | 环节 | 输入 → 输出 | 与相邻环节的分界 |
|---|---|---|---|
| L1 | 加速器设计 | 架构/PDK → 网表（GDS） | 到流片为止；不含制造 |
| L1 | EDA 与 IP | 设计需求 → 工具授权/核 | 卖工具不卖芯片；按席位/流片计费 |
| L2 | 晶圆代工 | 光罩 + 硅片 → 加工好的晶圆 | 不含切割封装 |
| L2 | 半导体设备 | 零部件 → 机台 | 卖给代工/存储厂，不卖给设计公司 |
| L2 | 材料 | 原料 → 硅片/光刻胶/特气 | 与设备同层但不同环节，交期与认证周期不同 |
| L3 | 先进封装（CoWoS/SoIC/EMIB） | 逻辑晶圆 + HBM 堆叠 → 封装模组 | 与代工的分界：出封装线才算这一环 |
| L3 | HBM | DRAM 晶圆 → 堆叠颗 | 与普通 DRAM 的分界：TSV 堆叠 + 与 GPU 共封装 |
| L3 | 载板与 PCB/CCL | 树脂/铜箔 → 基板/板 | 与封装的分界：封装做在载板上 |
| L4 | 服务器 ODM | 模组 + 机箱 + 电源 → 整机/机柜 | 品牌厂与 ODM 的分界：谁做系统集成 |
| L4 | 交换与交换芯片 | 芯片 → 交换机 | 与光模块分界：交换是电域，模块是光域 |
| L4 | 光模块 | 光芯片 + DSP → 模块 | 按速率分档（400G/800G/1.6T），不同档不同产线 |
| L4 | 电源与液冷 | 器件 → 供电/CDU | 按 kW 计，不按台计 |
| L5 | 数据中心 EPC 与并网 | MW 配额 → 可上电机房 | 与 L4 分界：L4 交付机柜，L5 交付"能通电的壳" |

**边界不清的处理**：写"环节边界待裁定"并上报，不进骨架。**不许用"某某集团"顶替环节**——集团横跨多层，写进去骨架就废了。

## 五、五组基础换算（骨架的核心，必须给公式与算例）

### 4.1 产能 / 产量 / 良率 / 交期 / 库存（五个量不是一回事）

| 量 | 定义 | 常见误用 |
|---|---|---|
| 产能 | 满负荷能产多少（片/月、kW、柜/周） | 被当成实际产出 |
| 产量 | 实际产出 | 被当成可交付 |
| 良率 | 有效产出比例 | 只在爬坡期披露，稳态很少披露 |
| 交期 | 从下单到交付的周数 | 被当成产能（长交期可能是排队，不是缺产线） |
| 库存 | 可支撑天数 | 被忽略，导致"涨价=缺货"的误判 |

**关系式**：`可交付 = 产量 × 良率 − 库存消化`；`需求缺口 = 需求量 − 可交付`。
**报缺口必须写清分子分母**：是"产能缺口"还是"交期缺口"，两者的政策含义不同。

### 4.2 片 → 颗 → 位元 → GB

- CoWoS 报 **片/月（wpm）**；一片能切多少颗取决于封装尺寸与光罩倍数。
- HBM 报 **位元（bit）** 或 **$/Gb**；一颗 HBM 的容量按 GB 记，堆叠层数（8-Hi/12-Hi/16-Hi）决定单颗容量。
- GPU 报 **颗**，单卡 HBM 容量按 GB 记。

**算例（量级示例，口径以来源为准）**：单卡 HBM 216–288GB、整机 8 卡 ⇒ 单机 1.7–2.3TB；若单颗 HBM4 单价 100–180 美元、单卡 8 颗 ⇒ 单卡 HBM 成本 0.8–1.4 千美元。
**用途**：判断"存储涨价"对整机 BOM 的传导幅度；不许直接当预测。

### 4.3 带宽 → 端口 → 模块数

- 交换机报 **Tbps** 或**端口数**；光模块报 **只**。
- 换算：`模块数 = 端口数 × 每端口模块数`；`端口数 = 总带宽 / 单端口速率`（800G = 8×100G 通道）。
- **易错点**：800G 与 2×400G 是不同封装方案，只数不能直接相加；CPO 把模块从"面板可插拔"移到"共封装"，模块数会骤降而带宽不变。

**算例**：一个 51.2T 交换芯片，按 800G 端口 ⇒ 64 个端口；按 1.6T ⇒ 32 个端口。同一颗芯片，两种速率假设下"模块需求"差一倍。

### 4.4 MW → 机柜 → GPU 当量

- 数据中心报 **MW**；机柜报 **kW/柜**；芯片报 **颗**。
- 换算：`柜数 ≈ 总功率 / 单柜功率`；`GPU 数 = 柜数 × 每柜 GPU 数`。
- **易错点**：单柜功率从风冷 10–20kW 到液冷 120kW+ 差一个数量级；PUE 是设计值还是实测值会影响"总功率"口径。

**算例**：1GW ≈ 1,000,000kW；按 120kW/柜 ⇒ 约 8,300 柜；按 72 GPU/柜 ⇒ 约 60 万 GPU。这是"1GW 等于多少卡"的量级答案，**不是预测**。

### 4.5 美元与 BOM 占比

整机价值量按环节拆分：加速器芯片、HBM、先进封装、载板、PCB、光模块、交换、电源、冷却、组装。
拆分必须写来源与口径（是售价拆分还是成本拆分；含不含软件与服务）。

**用途**：判断"某一环涨价 10%"对整机成本的影响。**禁止**用自己的拆分去覆盖来源的拆分；两者不一致时并列。

## 六、瓶颈判据（建构件必须给的"紧不紧"信号）

| 信号 | 怎么读 | 反例 |
|---|---|---|
| 交期拉长 | 交期是先行指标；52–78 周级别说明排队严重 | 交期长也可能是客户提前锁产能 |
| 预订比例 | "全年产能已售罄/预订 70%"类表述 | 口头预订可取消 |
| 供需缺口百分比 | 需写清是产能缺口还是需求缺口 | 缺口 20% 与 50% 的传导完全不同 |
| 替代方案进展 | EMIB/玻璃基板/其他封装路线的导入进度 | 有替代 ≠ 已量产 |
| 价格与代际 | 新一代（如 HBM4）报价倍数 vs 上一代 | 报价不等于成交价 |
| 扩产计划 | 从 X 片/月到 Y 片/月的时点 | 设备安装与验证有 12–24 个月滞后 |

**建构件要写清"这一环现在的瓶颈形态"**（产能/交期/良率/材料/电力），因为四者的破解方式不同。

## 七、建构件自检（八条，缺一不合格）

1. 六层里覆盖了哪几层、有没有混层
2. 每个环节写了"输入→输出"
3. 主体落到产品/工序，不是集团名
4. 每个量有单位，且写了"是什么、不是什么"
5. 换算有公式 + 一个能用已知数验证的算例
6. 频次与下一次发布日期
7. 瓶颈形态与可观察信号
8. 缺口具名

**不合格的典型**：只有公司名单（缺 2、4、5）；只有"景气度高"（缺 3、7）；把不同层塞进一张表（缺 1）。

## 八、红线

1. 不许把公司名单当产业链（缺输入输出、缺口径、缺换算）。
2. 不许混层比较（片/月 vs 位元 vs 只 vs MW）。
3. 不许把产能当产量、把出货当需求、把交期当产能。
4. 不许用集团名顶替环节。
5. 不许自造份额；份额必须有发布方。
6. 不许在本册里跑"某个量变了多少"——那是《产业链跟踪》。
