# 部署与调度（移植到 macOS / 交给宿主 Agent 定时）

> **一句话**：`pipelines/` 是一套**无状态 CLI**，不含调度器。它跑在哪台机器上，
> 就由那台机器上的宿主 Agent 负责定时唤起。本文给的是**与具体 Agent 无关**的接法
> （Codex / WorkBuddy / 系统 cron 都适用）。

---

## 1. 为什么管线里没有 cron

SKILL.md §9 明文禁止：不许在管道里加 `cron` / `APScheduler` / `systemd`。

理由是**单一真相源**：定时若同时存在于"管道代码"和"宿主的自动化任务"两处，
改了一处忘了另一处，就会出现"代码里写着每天跑、实际根本没触发"这种静默失效。
所以定时一律归宿主，管道只保证**一条命令能跑完并且如实报态**。

## 2. 依赖清单（实测，只有这些）

| 依赖 | 版本 | 必需性 | 用途 |
|---|---|---|---|
| Python | ≥ 3.10 | 必需 | 代码用了 `X \| None` 语法 |
| PyYAML | ≥ 6.0 | 必需 | 读 `channels.yaml` / `t3_sources.yaml` |
| pytest | ≥ 8 | 可选 | 跑 `pipelines/tests`（38 条离线契约测试） |
| Node.js | ≥ 18 | **仅 T3 需要** | `playwright-core` 是 Node 包 |
| `playwright-core` | ^1.64 | 仅 T3 需要 | 浏览器会话（在根 `package.json` 的 devDependencies） |
| Chromium 系浏览器 | — | 仅 T3 需要 | Edge / Chrome / Chromium 任一 |

**不装 Node / 不装浏览器也能跑 23 个非 T3 的型**——T3 型会如实报
`浏览器会话不可用`，不会拖累其他型。

## 3. 移植到 macOS：六步

```bash
# ① 拉代码（不要带 _landing / _profiles / _runs，那些是本机产物）
git clone <repo> ~/InvestSigh-Read && cd ~/InvestSigh-Read

# ② Python 依赖
python3 -m pip install -r pipelines/requirements.txt

# ③ 只跑非 T3 的型：到这里就已经可用，先验一遍
python -m pipelines selftest
python -m pipelines health --class 01

# ④ 要 T3 才需要下面两步
npm install                        # 装 playwright-core
#    浏览器用系统已装的 Edge/Chrome（Mac 默认路径已在代码里），
#    或显式指定：
export PIPELINES_BROWSER="/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge"

# ⑤ T3 首次登录（需人扫码一次；Agent 按 docs/T3Agent引导.md §1.3 开口）
python -m pipelines login --source zsxq

# ⑥ 全量验收
python -m pytest pipelines/tests -q      # 38 passed
python -m pipelines health               # 逐型看态
```

### 路径相关的三个事实

1. **代码里没有任何盘符硬编码**（已全仓 grep 确认）。所有路径都从
   `Path(__file__).resolve().parents[n]` 推导，换目录/换系统自动适配。
2. **浏览器位置唯一平台差异**已在 `_kit/browser.py` 里用候选表覆盖
   （win32 / darwin / linux 各一套），并支持 `PIPELINES_BROWSER` 环境变量覆盖。
3. `pipelines/.gitignore` 已排除 `_landing/` `_profiles/` `_runs/`
   —— 这三样**不应该跟着代码走**，到新机器重新生成。

## 4. 环境变量（只这几个，全部可不设）

| 变量 | 作用 | 缺省行为 |
|---|---|---|
| `PIPELINES_BROWSER` | 指定 Chromium 系浏览器可执行文件 | 按平台候选表找，找不到报 `BrowserUnavailable` 并说明要装什么 |
| `FRED_API_KEY` | `06-macro-cycle` 的宏观序列 | 缺则 `unavailable(no_api_key)`，**不是失败** |
| `BLS_API_KEY` / `BEA_API_KEY` / `EIA_API_KEY` / `USPTO_API_KEY` | 可选增强 | 缺则对应子项跳过 |
| `PIPELINES_FRED_KEY` | 指向别的环境变量名（多环境切换用） | 默认读 `FRED_API_KEY` |

申请步骤见 `pipelines/_keys/README.md`。**key 只走环境变量，不进仓库任何文件。**

## 5. 定时任务：交给宿主 Agent

### 5.1 三个任务的语义（与实现无关）

| 任务 | 何时 | 干什么 | 输出 |
|---|---|---|---|
| **盘前自检** | 交易日开盘前 | `selftest` + `health` | 只报"哪些型不是 ok" |
| **盘后采集** | 美股收盘后 | `run --class 01…07` | 读 `_runs/<今天>/*.json`，逐型报三态 |
| **周度补跑** | 每周五 | COT（周五发布）+ 媒体 + T3 巡检 | 同上报态 |

### 5.2 cron 表达（给系统调度器，或参考着填宿主的定时配置）

```cron
# 美股周一~周五收盘 ⇒ 北京时间次日（周二~周六）凌晨。
# 06:00 北京时间 ≈ 美东 18:00（夏令时）/ 17:00（冬令时），EDGAR 当日文件已归档。
0  6 * * 2-6   cd $HOME/InvestSigh-Read && python -m pipelines run --all --as-of $(date +\%F)
30 8 * * 2-6   cd $HOME/InvestSigh-Read && python -m pipelines selftest && python -m pipelines health
0  7 * * 6     cd $HOME/InvestSigh-Read && python -m pipelines run --type 07-position-flow --as-of $(date +\%F)
```

> **注意 `--as-of $(date +%F)`**：这给的是**运行日**。SEC 的年度件在窗口内 0 件是
> 正常结果（判 `empty`，不是故障），别因为"今天没取到 10-K"就去调参。

### 5.3 交给宿主 Agent 的 prompt（照抄，Codex 也适用）

```
在仓库根目录（含 pipelines/ 的那一层）执行：
  python -m pipelines run --all --as-of <今天 YYYY-MM-DD>

然后读 pipelines/_runs/<今天>/*.json，按下面规则汇报，不要自己判断数据含义：

1. 每个 type 都读 status，不要只看退出码（一类里有 6-7 个型，各有各的态）。
2. status=ok        → 报"取到 N 件：<artifacts 里的 id>"
3. status=empty     → 报"查了 <gap.checked_scope>，窗口内确实无新件"
                      ★ 这是合格结果，不要重试、不要找人
4. status=unavailable →
   - 若 gap.action_required.kind = dev_pin_selector → 这是**代码/配置**的活，
     不要找人，报一句"选择器待钉版"即可
   - 若 gap.action_required.kind 是 login / confirm_account / manual_export
     → 按 docs/T3Agent引导.md 的话术转述 who/needs/command/steps，然后**停止重试**，等人回话
   - 若没有 action_required → 只报 gap.absent_reason 与 checked_scope
5. status=failed    → 贴 failed[] 原文，最多重试 1 次
6. status=not_run   → 说明"该型是查表册，本管道不取数"（不是失败）

禁止事项：
- 不许把 unavailable 写成"无风险 / 已覆盖 / 无需关注"
- 不许把 empty 写成"没有材料"（少了 checked_scope 就是撒谎）
- 不许为了让命令成功而修改 channels.yaml 或代码
```

### 5.4 如果宿主是 Codex

Codex 有创建定时任务的能力，接法与上表一致，只需注意两点：

1. **prompt 里不要出现宿主持有的路径变量**（如 `$HOME/InvestSigh-Read`），
   要写成"在仓库根目录执行"——搬运到老板机器时目录名会变。
2. **工作目录要显式指定**：Codex 的自动化任务如果从别处启动，`python -m pipelines`
   会找不到包。prompt 第一句写"`cd` 到含 `pipelines/` 的目录"。

## 6. 验收"移植成功"的判据（不要只看"命令没报错"）

```bash
# ① 结构自洽
python -m pipelines selftest                     # 应输出「selftest 全绿」
# ② 契约不破
python -m pytest pipelines/tests -q              # 应 38 passed
# ③ 源可达（不落材料）
python -m pipelines health                       # 逐型看，ok 应有 23 个左右
# ④ 入库形态
python -m pipelines audit                        # A1–A5 全过；有重复会逐条点名
# ⑤ 单型实跑（挑一个不依赖 key 的）
python -m pipelines run --type consensus-gap --as-of <今天>
ls corpus/materials/07-consensus-gap-<今天>-*/     # 应有 4 个文件
```

五条都过了才算移植成功。**只跑第 ⑤ 条会漏掉结构性问题**（型数、Adapter、字段契约）。

## 7. 搬到老板机器后，第一次必然要人做的事

| 事项 | 谁做 | 一次性? | 说明 |
|---|---|---|---|
| zsxq 扫码登录 | 老板本人 | 是（会话过期需重扫） | 只扫码；怎么做见 `docs/T3Agent引导.md §3.1` |
| ima 导出文件 | 老板本人 | **每次都要** | ima 无程序化通道，只能客户端手动下载；话术见 `docs/T3Agent引导.md §3.3` |
| FRED key 申请 | 谁用谁申请 | 是 | `pipelines/_keys/README.md` |

除了这三项，其余 23 个型在装好依赖后即可无人值守运行。
