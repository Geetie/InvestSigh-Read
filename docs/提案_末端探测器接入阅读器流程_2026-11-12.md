## 二、修正后的设计前提（三条硬事实，全部可复验）

1. **网络本体确实不能进阅读器**（红队确认站得住）：一批一跑、白名单 7 件、可写边界 `output/<标的>/<材料id>/`，容不下 36 节点整套搬入。用户裁定正确。
2. **全库唯一真正在跑的机器钩子是 `server/check.mjs`**：批 agent 定稿前判门，实卡全在 `output/` 被它校验，直连「帮老板读得更快」这条主目标。
3. **末端探测器在阅读器里的可行形态是「判据 / 守卫」，不是运行时推理器**：不读原材料、不另跑一次 LLM 判断、不建新账。网络本体留在文档与 `#/network`，作为判据的设计依据与格枚举来源。

## 三、末端是什么：5 个末端 → 5 条判据族（不是 5 个推理器）

| 末端探测器 | 在阅读器里以什么形式运行 | 检查什么（机器可执行） |
|---|---|---|
| **E1 盈利腿** | check 的一条格级语句守卫 | 卡里凡出现「动收入／利润率／再投资格」的语句，**必须写实际格名**，不得只有 `M-2` 这类裸代号 |
| **E2 倍数·风险腿** | 同上 | 风险/竞争/政策类格级语句同上；依据区必须有 `p.N` 出处 |
| **E3 配置腿** | 同上 | 现金/融资/回购类格级语句同上 |
| **CRED 可信度调节** | 软观察（不硬拦） | 依据若是「据某机构称／某渠道称／第三方口径」，检查有没有标信源层；`proxy_tier` 这类参数**卡里没有，不假装能算** |
| **T1 收束** | 软观察 | 卡里若给了格级结论，检查有没有「核过了不用改 / 仅登记」这类收束声明；**不要求每张卡都必须有**（否则存量 601 份全违规） |

**统一约束（沿用既有真源，不自创）**：键＝格名＋口径、禁裸代号、禁节点名做提案键、依据写 `p.N` 且回溯到卡面依据区、只提案永不改估值模型。出处：`RUN-PARALLEL.md:27`、`建模_v1.md:152,164`。

**诚实边界**：这一形态下末端探测器**不新增信息**，它的价值是把批 agent 已经在做的归格判断**变成可机检的质量门禁**——让老板读到的格名是实际含义而不是代号，让依据可回溯。这就是「接入阅读器」能有、且仅有的收益；若要「新增信息」，见第八节阶段 2（另批）。

## 四、在哪个环节：check 定稿前判门（唯一有物理位置的环节）

```
备批(kit 7 件) → 批 agent 通读 → 构思/落纸写卡 → 〔node server/check.mjs 定稿前判门〕
                                                    ↑ 末端判据在这里跑
                                              → 交付 output/<标的>/<材料id>/material.md
```

- **不新增工序、不新增 automation、不改 kit 白名单、不改 batch 产物契约**；
- check 本来就在每份卡定稿前跑，接入零额外调度成本（项目纪律：pipelines 不含调度器，定时归宿主自动化）；
- 判门结果**直接反馈给批 agent 返工**——这就是消费端，解决 D6；
- 不再画「卡入库 → check → 收束」这种不存在的流程（红队 D2 纠正）。

## 五、怎么运行、怎么组织

**触发**：`node server/check.mjs [材料id]`（现有命令，参数不变）。
**输入**：正在定稿的那张 `material.md` 的答案区＋依据区；**不读三本账、不读分册、不读网络本体**（避免 D1 的「清单里没有映射源」）。
**输出**：新增一段**软观察**（不拦交付）：格级语句命中数、裸代号命中数、依据缺 `p.N` 命中数、信源层未标注命中数；单卡明细打到控制台。
**起步形态**：软观察，全库跑一次量基线 → 误报率低且规则稳定后再议是否升硬门禁（与「登记题守卫两步走」同款纪律）。
**组织**：只改 `server/check.mjs` 一个文件；**不新增目录、不新增账本、不新增字段、不改卡格式、不改 RUN-PARALLEL / 模板 / 34 分册 / 写法规范**。红队 I1 指出的「check 改动被零改动清单漏列」，本版如实列为唯一真源改动；也因不建 `_ledger-*.md` 新账，规避了 `check.mjs:220-236` 账本算术守卫的误伤与 `output/meta/` 语义混用（I7）。

**关于集中映射表（D1 的修法）**：本阶段**不建**。理由：建表要动 34 分册、且现有篮子列是裸代号＋一题多格＋判断指令，成本远超阶段 1 收益。先以「是否含 M-x 裸代号 / 是否写了实际格名」这类**无需枚举表的最小模式**跑观察；若数据证明值得，二期再建集中、版本化的「(分册,Q号)→格名＋口径」真源，并把「归格」如实标成判断而非规则。
