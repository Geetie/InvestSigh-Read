# 自动化任务定义（交给宿主 Agent 创建）

> **本包不含任何调度器**（`SKILL.md §9` 明令禁止）。定时由**宿主 Agent** 用自己的
> 定时能力创建：Codex 用它的 automation、WorkBuddy 用它的自动化任务、
> 或者干脆用系统 `cron` / `launchd`。
>
> 下面三个任务**可以直接抄**。建的时候注意：**prompt 里不要写死本机绝对路径**
> （搬运到老板机器时目录名会变），一律写"在仓库根目录执行"。

---

## 总览

| 任务 | 建议时间 | 耗时 | 失败影响 |
|---|---|---|---|
| **A. 盘前自检** | 交易日 08:30 | ~1 分钟 | 只报警，不影响采集 |
| **B. 盘后采集**（34 型） | 交易日 06:00 | 3–10 分钟 | 当天无新数据 |
| **C. 知识星球抓取** | 交易日 06:30 | 5–15 分钟 | 当天无星球 PDF |

三个分开建，**不要合成一个**——B 挂了不该拖累 C，C 要人扫码也不该卡住 B。

## 任务 A：盘前自检

**cron**

```cron
30 8 * * 2-6
```

> 为什么是周二到周六：美股周一~周五收盘，北京时间次日凌晨才有当日数据。
> 08:30 是开盘前留给你处理问题的时间。

**命令**

```bash
cd <仓库根>
python -m pipelines selftest
python -m pipelines health
```

**给宿主 Agent 的 prompt（照抄）**

```
在仓库根目录（含 pipelines/ 的那一层）执行：
  python -m pipelines selftest
  python -m pipelines health

汇报两件事，不要多写：
1. selftest 是否「全绿」。不是全绿就把失败项原文贴出来。
2. 哪些型不是 ok：贴「型键 + 状态 + 原因」。
   - 若该型带 action_required：按 who / needs / command 转述，并说明「需要人做」
   - 若是 map：说明「查表册，本管道不取数」
   - 若是 unavailable 且无 action：只报原因，不要建议重试

不要重试，不要修改任何文件，不要装依赖。
```

**判据**：`selftest` 输出「全绿」；`health` 里 ok 型 ≥ 20 个。

## 任务 B：盘后采集（34 型）

**cron**

```cron
0 6 * * 2-6
```

**命令**

```bash
cd <仓库根>
python -m pipelines run --all --as-of $(date +%F)
```

**给宿主 Agent 的 prompt（照抄）**

```
在仓库根目录（含 pipelines/ 的那一层）执行：
  python -m pipelines run --all --as-of <今天 YYYY-MM-DD>

然后读 pipelines/_runs/<今天>/*.json，**逐型**汇报。不要只看退出码：
一个类里有 6-7 个型，各有各的态。

每个 type 按 status 处理：

1. ok        → 报「取到 N 件：<artifacts 里的 id>」
2. empty     → 报「查了 <gap.checked_scope>，窗口内确实无新件」
               ★ 这是合格结果，不要重试、不要找人
3. unavailable
   - 有 action_required：
       kind=dev_pin_selector → 这是配置的活，不要找人，报「选择器待钉版」
       其它 kind（login/confirm_account/manual_export）→ 按 who/needs/command 转述，
         然后**停止重试**，等人回话
   - 没有 action_required：只报 gap.absent_reason，不要建议重试
4. failed    → 贴 failed[] 原文，最多重试 1 次
5. not_run   → 说明「该型是查表册，本管道不取数」，不是失败

最后跑一次入库体检并附结论：
  python -m pipelines audit

报告末尾附一行总账：ok=N empty=N unavailable=N failed=N。
```

**判据**

- 报告存在：`pipelines/_runs/<今天>/01.json` … `07.json`
- `audit` 的 A1–A5 无新增违例
- 若某型 `failed`，**不要自己改代码让它变绿**

## 任务 C：知识星球抓取（三段式，含**必须的判读步骤**）

**cron**

```cron
30 6 * * 2-6
```

**给宿主 Agent 的 prompt（照抄）**

```
在仓库根目录按顺序做三件事。

① 采集（不分型）：
   python -m pipelines intake --as-of <今天>
   产出 pipelines/_landing/zsxq/<今天>/：*.pdf + *.txt + _intake.json
   若输出「采集 0 份」：说明当天没有新 PDF，或全部星球被拒（看 _intake.json 的 skipped），
   如实汇报后结束，不要重试。

② 判读（这步不能省）：
   读 _intake.json 的 items[]，对每份看 head（不够就读同目录的 <文件>.txt）。
   ★ 判读依据在 corpus/prompts/03-型/ 下的手册，**先读手册、再读材料**：
       投行研报.md / 独立研究.md / 专家纪要与渠道交流.md / 媒体分析.md / 共识与评级档位.md
     每份手册开头写着「这是哪一类」，后面还有必过项 / 问句表 / 常见坑 / 红灯信号，
     那些才是判据。不要凭印象，也不要用别处抄来的二手总结。
   ★ 不许按星球名推断型：同一星球可能同时发研报和访谈（实测 Dots 一次发两样）。
   写 mapping.json 放同目录：
     [{"file":"xxx.pdf","group":"...","title":"...","type":"03-xxx",
       "evidence":"依据《XX》手册的哪一条（必填，不许写‘看着像’）"}]

③ 入库：
   python -m pipelines ingest --mapping "pipelines/_landing/zsxq/<今天>/mapping.json"
   输出「入库 N 份｜问题 M 条」。有问题就逐条贴出来，不要跳过。

最后汇报：每份的「文件名 | 判定型 | 依据一句话」，以及入库总数。
如果 intake 报「官方通道未开通 Skill 权限」，说明那批星球要走浏览器通道：
   python "pipelines/03-卖方与共识/zsxq_browser.py" --all-rejected --as-of <今天>
若它报「内容保护（星主禁止）」：如实说拿不到，**不要尝试绕过**。
如果 ingest 报「缺 evidence」：说明你没写判型依据，补上再跑。
```

**判据**

- `_landing/zsxq/<今天>/_intake.json` 存在
- 每份入库材料的 `meta.classifyEvidence` 非空
- `pages.json` 的 `pageCaliber` = `physical_page`，`pageCount` = 实际页数
- `needsExtraction=false`（除非原 PDF 是扫描件）

**注意**：这一步**不适合全自动**——判读需要读内容，是 Agent 的活，不是 cron 能完成的。
所以这个任务必须由**能读文件的 Agent** 执行，不能只挂个 shell 脚本。

## 三个任务的共同纪律

| 纪律 | 原因 |
|---|---|
| **不许在管道里加调度器** | 单一真相源：定时只在宿主一处 |
| **不许把 unavailable 写成"无风险/已覆盖"** | 缺数据 ≠ 没风险 |
| **不许把 empty 写成"没有材料"** | empty = 查过确实没有 |
| **不许改 `channels.yaml` 让报错消失** | 那是把缺口改成假绿 |
| **同一缺口一天只提一次** | 反复催会让人关掉整个流程 |
| **重试只对 failed，不对 unavailable** | 源不存在，重试永远不成功 |

## 如果宿主是 Codex

Codex 有创建定时任务的能力，接法同上，注意两点：

1. **prompt 第一句写"cd 到含 pipelines/ 的目录"** —— Codex 的定时任务可能从别处启动，
   不指定工作目录会 `No module named pipelines`。
2. **不要用 `$HOME/xxx` 这类宿主变量**，写"仓库根目录"让 Agent 自己找。

## 如果宿主是系统 cron

直接抄上面的 cron 表达式 + 命令。注意 Windows 的 `cron` 是任务计划程序，
`$(date +%F)` 要换成 `%date%` 或让脚本自己取当天日期（`zsxq_daily.py` 默认就是今天，
可以省掉 `--as-of`）。
