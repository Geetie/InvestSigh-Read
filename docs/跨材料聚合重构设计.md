# 跨材料聚合 · 重构设计

> 目标：让"答案在材料之间"的题变得可答——通过**提示词、文件夹契约、程序入口**三个杠杆，重塑 agent 的运行时路径。
> 需求基线：全 34 型普查（《跨材料依赖盘点-全34型》）——281 题中 106 道配对题（同型跨份 35／跨类 33／跨标的 3／非语料 35）。
> 今天的三个实证，构成本设计的经验基础：
> ① **白名单测试成功**——干净 agent 拿"写法规范＋分册＋模板＋主材料＋3 份配套"跑出了达标卡，证明 agent 运行时路径可以被一份清单塑造；
> ② **8-K 重抓事故**——材料 11-04 重抓后含全文新闻稿，旧卡还停在索引页，卡与材料脱节没人发现，证明材料有生命周期、卡需要指纹；
> ③ **"需跨批（交主控）"空转**——占位符存在一个月，主控从未接住过，证明跨批不能靠口头移交，要靠程序和契约。

## 一、设计原则（五条）

1. **真源唯一，延伸到"需要什么"**：每道题需要什么件，只在问句表的**需件列**声明一次；kit 组装、守卫、文档全部读它。这是写法层重构（写法规范.md 单一真源）的同一模式。
2. **材料只读，卡与账分家**：`corpus/materials/` 永远只读；agent 产物（卡）与系统资产（账本）分开落位，写边界矩阵见第五节。
3. **程序做解析，agent 做判断**：找文件、对日期、算指纹、比差集——机器干；读数、判档、写答案——agent 干。入口程序输出的不是结论，是**白名单与原料**。
4. **空格死命令跨路径一致**：kit 缺件时，缺哪档就按哪档降级（单份题照答、配对题整节删掉），不因"有程序"就把缺件写成 essay。
5. **一切引用带指纹**：账本行、对照卡引用的每个数，指向来源卡的指纹；卡重填则引用自动标过期（治 8-K 事故）。

## 二、三个杠杆 × 三条运行时路径

| 路径 | 干什么 | 提示词 | 文件夹契约 | 程序入口 | 触发器 |
|---|---|---|---|---|---|
| **A · 单份遍**（现状保留） | 一份材料一张卡，答单份题 | 型分册问句表＋写法规范 | `corpus/materials/<id>/` 只读 → `output/<标的>/<id>/material.md` | `kit.mjs <id>`（组装白名单） | 新材料加工 automation |
| **B · 对账遍** | 数值对账（指引 vs 实际）＋措辞演变（上季 vs 本季） | 对账卡模板＋写法规范 | 读 `output/<标的>/` 相关卡（只读）→ 写 `output/<标的>/_ledger-*.md`、`_对照-*.md` | `reconcile.mjs <标的>` | 新 01 财报表入库／新同型卡入库 |
| **C · 命题遍** | 跨标的主张核查（"行业逆风同业也这么说吗"） | 命题核查模板＋写法规范 | 读 `_claims.md` ＋ 任一相关标的卡 → 更新 `_claims.md` 与主张方卡的旁证格 | `reconcile.mjs --claims` | 任何相关材料入库（事件驱动） |

三条路径共享同一个 check（R1–R3）与同一个写法规范。**运行时路径从一条变成三条，但 agent 每次只走一条**——每次派发仍是一个白名单、一份提示词、一个产物，今天的测试形态不变，变的是清单由程序解析、产物多出账与命题两种类型。

## 三、杠杆一：提示词改动（四处）

1. **问句表加"需件列"**（34 型逐题，机器可读记法）：
   `| … | 需件=单份 |` 或 `需件=同场:主会,EX-99.1;跨期:同型上1-2期;对账:指引账;跨标的:同业≥2;外部:行情`。
   空缺默认"单份"。kit.mjs 只解析这一列，别处再写"需要什么"一律视为漂移（与写法真源同纪律）。
2. **写法规范补一节"配对题落纸"**：跨材料事实写进正文时必须注明来源材料名；数字只允许来自 kit 白名单内的材料；kit 外的数字＝编造（今天 8-K 数字是合法范例——它在白名单内；假设它不在，就是违规范例）。
3. **"一批一跑"条款重写**（RUN-PARALLEL §1）：批的定义从"一份材料"改为"**一个答题环境**"——kit 清单＋对应提示词＋产物落点。跨期题不再写"需跨批（交主控）"，而是按需件列走 B/C 路径；kit 解析不出才写缺口。
4. **主件/分册瘦身**：分册保留认型与问句表；"怎么读"里与需件重复的取数描述删掉，指向需件列（防两处漂移——写法层重构的同一刀法）。

## 四、杠杆二：文件夹契约

```
InvestSigh-Read/
├── corpus/
│   ├── materials/<材料id>/          # 只读语料（现状不动）
│   │   ├── meta.json                # 扩展：标的、型、期间、来源、抓取指纹
│   │   ├── pages.json / content.md / exhibits/ / figures/
│   ├── events/<标的>/<事件日>.yaml  # 事件视图：指向成员材料 id（不复制文件）
│   ├── prompts/                     # 主件 + 分册(含需件列) + 写法规范.md
│   └── templates/
├── output/<标的>/                   # agent 产物区（现有卡不动）
│   ├── <材料id>/material.md         # 卡（A 遍产物）
│   ├── _ledger-guidance.md          # 账本：期间|指引|实际|指纹（B 遍产物，追加式）
│   ├── _对照-措辞演变.md            # 跨期措辞对照卡（B 遍产物，重写式）
│   └── _claims.md                   # 命题清单：谁说的|什么主张|已核几家|指纹（C 遍产物）
├── runs/kits/<材料id>.json          # kit 清单（程序产物，agent 白名单的机器形态）
└── server/                          # kit.mjs / reconcile.mjs / stale.mjs / check.mjs
```

契约要点：

1. **`_` 前缀＝系统资产**：`_ledger-*`、`_对照-*`、`_claims` 不属于任何一张卡，是标的级资产；写边界矩阵从"仅 `output/<标的>/<材料id>/`"扩展出这一类（规则改动，需 README §3.1.1 落字）。
2. **指纹契约（治 8-K 事故）**：`meta.json` 增加 `fingerprint`（对 content.md+pages.json 做 hash）与 `refetchedAt`；卡 frontmatter 增加 `source_fingerprint`。`stale.mjs` 比对：材料指纹 ≠ 卡指纹 ⇒ 卡标过期（阅读器显示"材料已更新，卡待重填"），B/C 遍引用该卡的行同步标过期。**8-K 那张卡就是第一个要重填的**。
3. **账本行格式**（追加式，永不改写历史行）：`| 期间 | 指引(原值) | 实际(值+指向卡指纹) | 偏差 | 重算于 |`。账行引用卡，卡过期则账行标过期、reconcile 重算。
4. **claims 行格式**：`| 命题 | 主张方(卡指纹) | 已核:同业卡×N | 状态:未获旁证/旁证成立/矛盾 |`。状态三值之外不发明第五种。

## 五、杠杆三：程序入口（三个新入口，两个已有）

| 程序 | 职责 | 输入 | 输出 |
|---|---|---|---|
| `kit.mjs <材料id>` | 解析该材料型的需件列 → 组装白名单：主材料、同场件（按 meta.json 的标的+日期+型匹配）、跨期件（同型按期间排序取 N 期）、账本/对照卡（存在则列入）、外部件（标注"E 档缺件"） | 型分册、全部 meta.json、output/ 卡索引 | `runs/kits/<id>.json` ＋ 提示词白名单文本段 |
| `reconcile.mjs <标的> [--claims]` | B 遍：拉账本＋相关卡，算差集、更新对照卡与账行；C 遍：拉命题清单，对新增卡做主张核查 | 账本、卡目录、指纹表 | 更新 `_ledger-*`、`_对照-*`、`_claims` |
| `stale.mjs` | 全库扫：材料指纹 vs 卡指纹；输出过期卡清单 | meta.json × 卡 frontmatter | 过期清单（阅读器标灰、reconcile 队列） |
| `check.mjs`（已有） | R1–R3 扩展一格：配对题答案里引用的跨材料数字，若 kit 清单内有对应材料，抽验其存在于该材料文本（防 8-K 式错配——今天数字是真的，但机检当时不覆盖） | 卡 + kit 清单 | 合格/不合格 |
| `template.mjs`（已有） | 需件列进入模板生成管线 | 分册 | 模板 |

**程序不做判断的红线**：kit.mjs 不因"材料像相关"而加件（只按需件列与元数据匹配）；reconcile 不写答案只登记（答案由派发的 agent 产）；stale 不自动重填。

## 六、与现有系统的接线

- **automation**：盘后采集（14:00）入库后自动跑 `stale.mjs`；新材料加工（15:30）的填卡阶段改为"kit → 派发 → check"；新增 reconcile 阶段（有新 01 财报表的标的才触发）。
- **阅读器**：卡过期标灰；账本/对照卡/命题清单作为新页面类型（读 `_` 资产）；kit 清单可展示"这道题用了哪些材料"——回答用户一直关心的"答案从哪来"。
- **写法层重构成果直接复用**：写法规范.md 不动（配对题落纸补一节）；空格死命令在 B/C 遍同样生效（账本不写"尚无数据"，没行就是没行）。

## 七、迁移与验收（四步，每步可验）

1. **需件列落库**：34 型问句表逐题标注（普查文档已给出每题档位，机械转录＋人工复核）；RUN-PARALLEL §1 重写。
2. **stale.mjs + 指纹契约先行**：改动最小、止血最快——8-K 卡当场被标过期，重填后验证。
3. **kit.mjs + A 遍改造**：新材料加工 automation 切换到 kit 派发；拿 Meta 2026Q1 追问会做首轮验收（对照今天的白名单测试——同一材料，程序组装清单 vs 我手拼清单，产物应同构）。
4. **reconcile.mjs + B/C 遍**：先手工建 Meta 指引账 4–8 期，reconcile 首跑验证 Q7 从空格变实答（账本查表）；旁证命题清单用普查里的 3 道 D 档题试运行。

每步的失败回退：A 遍可随时退回现状（kit.mjs 只是加了一层解析）；账本/claims 是追加文件，删除即回退。

## 八、明确不做（本期边界）

- **E 档（非语料 35 题）的数据资产**：行情、宏观数据库、平台流水——本设计只在需件列标记"外部:××"，采集与接入另立项；kit 对 E 档件一律输出"E 档缺件"，agent 按空格死命令处理。
- **我方假设账**（别人的解读 Q3）：属模型侧资产，落位 `valuation-model` 侧，本设计只留接口（需件列标"对账:我方账"）。
- **34 型之外的型**（AI 产业链地图补册等）：需件列照标，路径自动适用。

## 九、一句话

今天证明了一件事：**agent 的产出质量是运行时路径的函数**。这份设计把路径从"一份材料碰运气"变成"程序按需件清单摆好桌、agent 只做判断、账本记住一切"——三个杠杆各司其职：提示词声明需要什么，文件夹契约规定东西放哪、谁的指纹算数，程序保证桌上的东西齐全、新鲜、可追溯。

## 十、采集完整性：怎么保证"一个不落"

依托已有骨架（`pipelines/<类>/channels.yaml` 本就是型↔源的机器可读真源；`_runs/<日期>/` 已是逐日运行台账；`_landing/` 是落地区），加四个机制：

1. **先抓目录，再对账，后下载。** 每个渠道第一步只抓"目录"（SEC submissions JSON／IR 事件日历／星球话题列表）——目录轻量、必达。目录条目与入库记录按来源 URL＋指纹对账，**差集＝漏**。这把"漏"从运气问题变成算术问题。
2. **水位线只在成功后推进。** 每渠道在 `_runs/<日期>/` 记本次看到了什么、收到了什么；失败不推进水位，下次 catch-up。已入库的靠指纹幂等跳过；**指纹变化＝新版本**（8-K 重抓即此情形），重抓后触发 stale，不静默覆盖。
3. **事件契约：应到清单挂在事件上，不挂在某一次抓取上。** 一次财报事件应到：8-K、EX-99.1 新闻稿、投资者演示文稿、主会逐字稿、追问会逐字稿、10-Q——它们**陆续到货**（EX-99.1 常晚于 8-K 数日），事件视图（`corpus/events/<标的>/<事件日>.yaml`）逐项打勾：到了才勾，逾期未勾＝**missing**。EX-99.1"后来才进库"那一类洞，从此由事件视图兜住。
4. **缺口台账：四态语义，永不静默关闭。** 项目既有 ok／empty／failed 三态，增加第四态 **missing**（目录说有、库里没有）：missing 必须进台账，直到材料到货（自动关）或显式豁免＋理由（人工关）。empty＝目录里本来就没有＝合格结果（沿用既有纪律）；failed＝可重试；**"一个不落"的准确含义＝missing 清单每天可见、非空必有人管**，而不是"从不出错"。

## 十一、存放：一份材料怎么供多道题共同取用

1. **meta.json 扩展为"寻址档案"**：标的、型、期间／事件日、accession、来源 URL、指纹、语言、文件清单。多道题找材料走同一个索引（kit.mjs 解析它），不靠谁记得目录名。
2. **事件视图是指针清单，不是拷贝**：`corpus/events/<标的>/<事件日>.yaml` 列成员材料 id——一场财报事件的六份材料散在六个材料目录里，事件视图让"同场件"解析 O(1)，且坚持单一拷贝（复制文件必然产生版本漂移，8-K 事故的变体）。
3. **取用粒度保持在材料级**：不同型读同一份材料的不同侧面（10-Q 材料供 10-Q 卡的科目题、供电话会卡的指引对照、供账本的实际值），但都整份读——研读纪律禁抽样，聚合设计不引入页级索引去破坏它。
4. **共同取用全程可审计**：卡 → kit.json → 材料 id 链条落盘。任何一句跨材料的话，都能沿"卡→当次 kit→材料"追出它读的是哪份文件的哪个指纹。

## 十二、型的细分在聚合中的角色（三个，缺一不可）

1. **需件列的宿主。** kit 之所以能"精确到题"，是因为每型问句表声明了每题需要什么。没有型，281 道题一锅烩，kit 只能把全部材料推给 agent——聚合就退化成大杂烩。型的细分是 kit 精度的来源。
2. **跨期与跨标的的配对键。** B 遍做"同一问题两季对照"，能配对的前提是两份材料**同型且相邻期**（追问会↔追问会、主会↔主会、同机构上版）；C 遍的旁证核查，配对键同样是型（别家的同型卡才够格当旁证）；跨类对账（02 的话 vs 01 的数）也要先知道两侧各是什么型、谁该拥有哪个事实。没有型，聚合连"什么和什么配"都算不出来。
3. **信源纪律的载体。** 跨材料引用时，**来源材料的型决定措辞**：公司原话可直述、卖方结论必须"某机构认为"、旁证只能当旁证、申报数字须引逐字。型的细分把 02 主件警告过的"信源层级混淆"（把别人的解读写成公司原话）变成聚合时的硬约束——同一份材料被多道题取用时，各型按自己的纪律取用，读法不互相污染（公司原话禁抽样、旁证只读结论页，这些差异也正是按型定义的）。

一句话：**型的细分管"怎么读"，聚合契约管"读哪些、从哪来、来齐没有"——两层正交，缺了任何一层，跨材料回答要么失明（找不齐），要么失真（读法混）。**

## 十三、变更运行手册（改型 · 改提示词 · 增减信息源）

**总原则：型、源、问句都是"声明"（yaml/md），kit／check／reconcile／stale 是型无关的引擎——扩展＝改声明＋跑重生成命令，不改引擎代码。** 材料与卡只增不改，历史永远可解释。

**改问句／读法（同一型内）**：
1. 改分册问句表（含需件列）→ 2. 跑模板重生成（template.mjs --all），`template_version` 自动 +1 → 3. 新卡走新版；旧卡按既有纪律标 legacy，不判、不伪造、不重跑；想重算的进 stale 重填队列排期。写法规范若改，全部型自动生效（单真源收益）。

**增型**：
1. taxonomy 加 sub id → 2. 新写分册（认型＋问句表＋需件列）→ 3. 对应类 channels.yaml 加 channel → 4. 模板重生成 → 5. 完。kit／stale／reconcile／check **零改动**——它们只读声明。唯一可能写代码的点：新载体格式需要新 adapter（如新的数据厂商）。

**减型／合并型**：taxonomy 标记 deprecated（不物理删——存量卡与材料还指着它）；channels.yaml 对应渠道置 paused；存量卡保留；kit/stale 自动不再覆盖。

**增信息源**：channels.yaml 加一段（slug／adapter／frequency／params）；**问句表不动**——需件列声明的是"要什么角色的话"（同场／上季／账本），不是"从哪家来"，两层解耦，两边各自演化。若新源带新事件类型，补对应事件的应到清单（第十章）。**减源**：置 paused，不删（历史材料指着它）。

**兜底**：任何变更后跑一遍 stale.mjs＋check.mjs 全量——漂移（模板没重生成、卡与材料错配）自动显形，不靠人记。

**成本所在**：真正贵的内容工作只有"把新分册的问句与需件写对"；机械部分（模板、白名单、对账）全部程序生成。历史上贵到肉疼的三种事故——两处真源打架、手改生成物、静默漂移——在本架构里被结构封死。
