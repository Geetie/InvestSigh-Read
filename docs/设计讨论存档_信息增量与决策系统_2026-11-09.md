## 一、起点：老板四反馈（原文）

1. "确实回答了问题，但是只回答了问题。有价值的信息不止于答案本身，还有得出答案所需的额外的信息和数据——得出答案的逻辑论证过程本身是有价值的。这些不可能通过问题来强制 agent 回答，因为 34 个型每个型的情况不一样。总之就是，答案是有价值的信息，但是得出答案的逻辑论证过程本身也是携带了很多有价值的信息的——因为所有投资者都能拿到的只有美国法律规定公司必须披露的那些 10-Q 之类的文本材料，所以大家的起点是相同的所得到的信息都是不完整的，但部分人会有自己的门路得到额外的信息。记住额外的高价值的信息就意味着在股票市场额外的胜率。所以大家都在通过各种文本材料获取更多信息，公司愿意并偶尔通过各种渠道传出来的、部分研究机构通过自己的门路获取观察到的，等等都是。所以要引导 agent 进行这方面的思考。但似乎仅仅靠提示词引导有些不够。"
2. "句子语法非常不通顺，读起来磕磕巴巴的，而且还很复杂。我觉得本质原因是从英文翻译过来的，带着英文的思维，而不是中文的思维，这个需要你探查调研一下。另外去看看 humanizer 这个 skill。"
3. "一些数据处理的口径问题。不同材料不同机构所用的口径可能是不同的——所以必须事先统一会计口径，老板不想阅读时还要自己去转换。"
4. "篇幅统一——因为统一的篇幅，导致部分重要问题本应该进行详细地描述，却因为统一的篇幅造成了信息量的丢失，问题 1 的部分原因也是这个。这些是需要找到根本原因并解决的问题。提出鲁棒的方案来修复。"

## 二、信息增量主线的演进（含三次用户纠偏）

### 第一版方案（被否）：模板固定节"推导与门路"

我提出每卡新增固定节承载"推导链/门路信息/对照异常"，配模板骨架与机器守卫。

> 用户否："推导与门路？门路？你这是生硬的抓了个关键词就往模板上按啊。门路是什么东西？门路是我提的，我的意思是那些机构和个人的自己的资源、关系和手段，这你放进去？模板固定骨架？你要什么样的骨架？会不会导致新的可读性下降的问题？"

**教训**：用户提出的概念（门路）是他的需求表达，不是要被直接做成模板槽位的名词。

### 第二版方案（被否）：专家清单写进读法列

学习报告（02/03 类）产出专家视角清单，计划写进读法列（追问阶梯、指引三件拆法、门路信号词汇表等）。

> 用户否："我还是没有看到有价值的东西……从你举的示例里，我并没有看到能让 agent 自主思考，自主判断哪些是逻辑论证过程自带的额外高价值信息的效果。"

**教训**：清单是预先教的知识，agent 只在清单范围内认东西——要的是自主思考机制。

### 第三版方案（部分被否）：三问程序 + 漏网之鱼候选清单

三问（反事实/知识账/停顿点）作为自主思考程序；漏网之鱼改候选清单制、三层过滤（高价值进格/中价值留痕/低价值判不登记）。

> 用户否（候选清单部分）："可读性，你把全部的有价值信息塞到一个格子里，而不是让有价值的信息在主问题的回答里就得到叙述和呈现，这他妈就是对可读性最大的伤害和降低，也拉慢了使用者阅读的速度，耽误了使用者获取有价值信息的时间。"

**教训**：增量信息必须**就地叙述**（写进所属题的答案），漏网之鱼只收无题可归的残留——把它当增量仓库是结构性错误。

### 用户的原则链条（原话，这是整个体系的骨架）

"说白了就是教并规范 agent 怎么在处理材料的过程中尽可能地像金融领域老手那样捕捉出所有的高价值信息——这涉及几个问题：
1. 重点是教导、规范和指引，不是让 agent 照本宣科地模仿，而是真的去思考什么是有价值的增量信息。这又涉及 2 了
2. 对高价值信息有一个体系化的高度抽象的原则指导性的判断标准，这个判断标准用来教 agent 怎么思考
3. 对高价值信息的判断标准具体到各类材料，不同信息上有具体的不同，需要进行细致的定义——因为对金融投资老手而言，有价值的信息对每个人而言也是不同的，因为每个老手的关注点和投资哲学逻辑是不一样的——所以对高价值信息的定义是首要的。
4. 那么问题就来了，高价值信息有哪些呢？高价值到底相对于什么是高价值？是有助于帮投资者做出投资决定的信息
5. 那么问题又来了，投资者投资股票进行决定的投资判断标准又是什么？
接下来还会引出一堆问题，你自己往下接着写，回答我，让我看看你的理解。
总之，本质是要教 Agent 进行思考和信息处理。一切列清单什么的方案，都不是很鲁棒，实现起来的成本很大，因为每个问题都需要细致地设计。判断标准是可以分册分情况可穷尽的，但是之前列的这些清单，我觉得没什么价值，是不可穷尽的"

### 我的推演（按链条续写，获用户认可："其他我都理解了，觉得可行"）

- **投资判断标准**：所有主动投资的本质=我的判断与市场定价隐含预期不同。三构件：预测未来现金流；评估市场已隐含的预期；比较取差。投资哲学差异只是时间尺度与确定性门槛的选择。
- **信息的价值定义**：信息价值 ≈ 推断权重 × 推断不确定性 × 证据强度 × 市场定价吸收度。四因子各管的判断：权重=该推断在估值里多重要；不确定性=越悬而未决新信息越值钱；证据强度=一手披露>公司口头>机构观察>渠道传闻；吸收度=发布即被全体吸收则增量归零。
- **可穷尽 vs 不可穷尽的分界**：宝藏**内容**不可穷尽（列"高价值信息长什么样"是死路）；宝藏**埋藏位置**可穷尽（每种材料的物理结构有限：电话会=问答环节与拒答处、研报=estimate 表与脚注、新闻稿=报表行与脚注、专家纪要=颗粒度异常处）。所以分册读法列该写的是"增量藏匿位置+判断程序"（藏宝图+探测器），不是信息内容清单。

### 术语归一（用户："到底有几问，到底有几个因子？每问都是为了什么，每个因子都是什么？"）

**一闸四因子**：

| 问 | 问什么 | 因子 |
|---|---|---|
| 1（闸门） | 这条信息触及哪个推断？ | ——（触及不到任何推断=不是信息，跳过） |
| 2 | 这个推断重要吗？ | 推断权重 |
| 3 | 这个推断还悬而未决吗？ | 推断不确定性 |
| 4 | 来源有多硬？ | 证据强度 |
| 5 | 市场已经消化了吗？ | 消化度 |

**两个操作手法**：反事实（答问 5：假设全体投资者都知道了这条，谁会改变预期或动作？会变=未消化=增量）；停顿点（答问 3：读材料时卡住/惊讶/需要外查的位置=不确定性所在=增量埋藏处）。
**知识账**（附加产出）：agent 为得出答案所用材料之外的东西（换算、行业常识、排除判断）就地写清——读者补不出的论证步骤就是 agent 贡献的增量。

### 已落地的规范修改【已落地】

- §增量发现：一闸四因子+两手法+知识账（corpus/prompts/写法规范.md）；
- §篇幅跟题目走 → §篇幅跟信息量走：句数上限降为参考中值，唯一硬约束=删句测试（升级为"删掉后读者对结论的信心和再验证能力不变才删"——论证步骤、可复核算式口径、超出法定披露的增量都算读者价值）；

### 第二版（被批评）："秉性口径"

我造了"三层口径（披露→秉性→他人）+秉性主尺"。

> 用户："你倒是把类级子 agent 们派出去啊！……不对，是'你说的这个分歧老板其实是有补充说明的'……"及更早："不是，怎么我说什么词，你就用什么词呢？你要拿相关的专业知识对我的这些说法进行思考和处理后再给我解决方案。我只是表达我的需求和我自己的定义，不一定准确和专业，我是没有相关知识的。"

**教训**（两次同类批评后确立的行为准则）：用户表达=需求与直觉（不一定专业准确），我的职责=专业转译+判断+暴露分歧给用户复核，不抓词照搬。

### 专业重构【已落地】：四视角标准口径

| 视角 | 口径 | 回答什么 |
|---|---|---|
| 有机增长 | 固定汇率（constant currency）、剔除并购并表 | 收入真实增长——剔除"买来的增长"与"汇率幻觉" |
| 核心经营利润 | 经营利润线剔一次性/非经常（重组、诉讼和解、减值） | 经营能力；**折旧摊销保留**（资本消耗是真实成本） |
| 自由现金流 | 经营现金流 − 资本开支（可分维持性/增长性） | 赚钱能力——现金视角，折旧在此自然回归 |
| 披露口径 | GAAP、公司财年、公司分部 | 法定事实锚，引用原数不许篡改 |

**关键专业判断**：老板"折旧干扰判断"的直觉正确，但字面执行（从利润删折旧）会隐藏资本消耗——资本开支前置期利润虚高、资产老化期利润虚低（Meta AI 数据中心折旧未来数年翻倍是现成反例）。解法=给 FCF 对照+写明维持性 vs 增长性资本开支，而非删项。

### 老板补充说明（折旧的条件性）

"像 AI 领域，像 Meta 这样的新云厂商，如果一家公司是重资产的公司，那么厂房云服务器的折旧这些都是必须算在内的，但对非重资产的公司就不一定了"——所以需要 agent 具体情况具体判断。但"像折旧这样需要具体判断的实在太多了，所以还得进行细致深入的设计——这也需要大量的知识、专业的视角，需要提案怎么处理，提案解决方案"。

### 口径判断框架提案【待批】（corpus/prompts/口径判断框架.md）

- 判断项分类学五类：A 资产成本确认（折旧摊销/资本化/减值）、B 收入确认（递延 bookings/gross-net/完工）、C 费用计量（SBC/重组）、D 汇总折算（汇率/并表/分部）、E 非经营（投资损益/利息/税项/少数股东）；
- 标的级**口径账**（账本体系新成员）：每公司一份政策表（判断项/政策/依据），维护决策树=查账→按政策→无则按判据模板判定并登记→属性漂移触发更新；

- 实施四阶段：判据模板补全（15–20 项）→ 口径账试点（META+轻重资产对照）→ 02 类学习报告挂接 → 铺开；

## 六、决策系统讨论（【搁置】，一字不落存档）

### 用户愿景（原话）

"如果真能把所有有价值的信息都收集起来，那完全可以实施构建另一套系统了。当前系统只是帮助老板阅读的更快的，另一套系统就是强大的决策系统了。当然会更复杂，因为只是把数据收上来没有意义，关键是怎么让信息流动起来——让 agent 进行决策，并且按照我们设计好的收束的轨迹和规则进行决策。"

### 我的收束轨迹方案（被搁置，内容存档）

四环闭环：

1. **读**（干活的 agent，每批材料）：带五问读材料；答案落各题格；增量三层过滤——高价值进漏网之鱼格、中价值候选清单留痕、低价值一行"判不登记"留痕；
2. **对账**（账本层：指引账/我方假设账/口径账）：漏网之鱼里的异常与承诺对照基石与历史账本逐条登记；跨卡冲突走"需跨批交主控"通道（单卡不许自己裁决）；漏网之鱼持续超 8 行=毕业成定向题；
3. **收束**（模型提案）：agent 的判断只以提案形态输出——格/现在/改成/依据/确信度，不许直接改模型；
4. **模型格更新**：批准后成为下一轮对照的新基石——闭环（新基石就是下一批的共同起点）。

防漂移设计：漏网之鱼格必须写候选清单痕迹（连"不登记"也留痕），check 哨兵查痕迹防程序形式化。

### 用户决定（原话）
