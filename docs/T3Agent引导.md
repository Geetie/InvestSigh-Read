# T3 操作手册（Agent 专用）

> **这是唯一一份 T3 文档。没有"给老板看的版本"——老板不看文档。**
> 他需要做的只有一件事：在键盘前扫一次码。其余全部由你（Agent）做完。
>
> 相关命令：`python -m pipelines doctor` / `setup --source zsxq|ima` / `health` / `run`

---

## 0. 分工（这条边界不能含糊）

| 谁 | 做什么 | 不该做什么 |
|---|---|---|
| **账号持有人（老板）** | **扫码**。说完这一步就结束。 | 读文档、改配置、装依赖、理解目录 |
| **你（Agent）** | 装依赖、建目录、拉星球 id、写 yaml、钉选择器、验证——**全部** | 替人扫码；自己点 GUI 去导出文件 |
| 管线 | 自动取数、如实报态 | 不含调度器（定时归宿主 Agent） |

凡是"能自动的"你必须自动掉；凡是"必须人的"，压到**只剩一次扫码**或**一句请求**。

---

## 1. 初始化（一次性，你全权负责）

### 1.1 先自检环境

```bash
python -m pipelines doctor
```

它把依赖分成三类报，每缺一项都给了**可执行的修法**：

| 分组 | 含义 | 缺了怎么办 |
|---|---|---|
| **必需** | 缺了整包跑不动 | 按提示装（Python ≥3.10、PyYAML） |
| **T3 专属** | 缺了只有知识星球/ima 不通 | 按提示装 Node / `npm install` / 浏览器 |
| **可选** | 缺了不影响主体 | 不用管；key 类会报 `unavailable(no_api_key)`，那是合格态 |

退出码：`0` 齐 ｜ `1` 缺必需 ｜ `2` 只缺 T3。

> **不要试图静默安装依赖**。doctor 只报告不安装，装的动作要么你显式执行，要么问人。

### 1.2 配 zsxq：一条命令

```bash
python -m pipelines setup --source zsxq
```

它按顺序做：环境自检 → 查会话 → **拉 `/v2/groups` 拿 `group_id` → 写回 `t3_sources.yaml`** → 跑 probe 验证。

三种结果，对应三种下一步：

| 输出 | 含义 | 你做什么 |
|---|---|---|
| `✓ 拉取星球列表：N 个` + `✓ 写入 group_ids` | 通了 | 去 §1.5 钉选择器 |
| `✗ 登录会话：没有会话` | 首次部署/换机器 | 去 §1.3 让人扫码 |
| `✗ 拉取星球列表：账号名下 0 个星球` | 登录成功但这个号没星球 | 去 §3.2 问人（**这不是故障**） |

写 yaml 时它只替换 `group_ids:` **那一行**，注释一个字不动（`yaml.safe_dump` 会吃掉全部注释，所以没用它）。改之前自动备份成 `t3_sources.yaml.bak`。

### 1.3 首次登录：怎么开口（唯一需要人的环节）

命令是 `python -m pipelines login --source zsxq`，但它会弹浏览器窗口——**这一步必须有人在场扫码**，所以要先把人叫过来。

**给人发这一条就够，不要分成三条**：

```
需要你扫一次码（约 1 分钟），扫完就再也不用了。

我现在弹一个浏览器窗口出来，里面是微信登录二维码，
你用手机微信扫一下、在手机上点确认就行。

如果窗口里只有一个「获取登录二维码」按钮没有二维码，
先勾选下面的《用户协议》，二维码才会出来。
```

然后你执行 `login`，等人回话。

**不要**：
- 把命令贴给人让他自己敲（他不该碰终端）
- 一次发三条消息（"我要登录了""你准备好了吗""扫了吗"）
- 人没回就重复执行 `login`（每跑一次弹一个窗，会把人烦死）

### 1.4 配 ima

```bash
python -m pipelines setup --source ima
```

它做两件事：建好落地目录 `pipelines/_landing/ima/<日期>/`，并**如实报告 ima 没有程序化通道**。

ima 这条**没有"配好就自动"的方案**：知识库只存在于桌面客户端里，网页版没有该视图、客户端不开放接口（六条路径都排除过，记录在 `t3_sources.yaml::ima.probed`）。
所以每次要新文件都得人在客户端里点一次下载——见 §3.3。

### 1.5 钉选择器（这是你的活，不要找人）

`setup` 只把 `group_ids` 搞定了，`item_selector` 还得钉。这一步**猜错比不猜更糟**，所以留给你看真实 DOM 后判断：

1. 用已存会话打开目标星球的列表页
2. 选中一条条目，复制**稳定**的 CSS 选择器
3. 填进 `pipelines/03-卖方与共识/t3_sources.yaml` 的
   `daily.item_selector` / `time_selector` / `attachment_selector`
4. 重跑 `python -m pipelines health --class 03`，确认不再是 `selector_not_pinned`

**稳定性判据**：`nth-child`、含随机 hash 的 class（如 `_item_a1b2c3`）、依赖 DOM 深度的后代选择器——改版必挂。优先用稳定的语义 class 或属性。

### 1.6 验收

```bash
python -m pipelines selftest                      # 全绿
python -m pytest pipelines/tests -q               # 38 passed
python -m pipelines health                        # 逐型看态，ok 应有 23 个左右
python -m pipelines audit                         # A1–A5 无违例
```

四条都过才算配好。**只跑其中一条会漏结构性问题**。

## 2. 日常运行：读报告，别看退出码

```bash
python -m pipelines run --all --as-of <今天>
```

产物：`pipelines/_runs/<今天>/<类>.json`。**报告 JSON 是唯一真源**，一个类里有 6–7 个型各有各的态。

| status | 该怎么说 | 禁止 |
|---|---|---|
| `ok` | "取到 N 件：`<artifacts[].id>`" | 不要说"数据完整" |
| `empty` | "查了 `gap.checked_scope`，窗口内确实无新件" | **禁止**说"没有材料" |
| `unavailable` | 见 §2.1 分诊 | 禁止说"无风险 / 已覆盖" |
| `failed` | 贴 `failed[]` 原文，最多重试 1 次 | 不许改代码让它变绿 |
| `not_run` | "该型是查表册，本管道不取数" | 禁止说"取数失败" |

`empty` 是最容易被误读的一态：`10-K` 一年发一次，7 天窗口里 0 件是**正确结果**，不是 SEC 挂了。

### 2.1 `unavailable` 的分诊（先看 `gap.action_required.kind`）

| `kind` | 该找谁 | 说什么 | 之后验证什么 |
|---|---|---|---|
| `login` | 账号持有人 | "请扫一次码"（§3.1） | 重跑 health 看是否变 ok |
| `confirm_account` | 账号持有人 | "登录成功但这个号没星球"（§3.2） | 看 `group_ids` 是否非空 |
| `manual_export` | 账号持有人 | "请导出这几个文件到 <目录>"（§3.3） | 看目录里有文件吗 |
| `dev_pin_selector` | **你自己，别找老板** | 去 §1.5 钉选择器 | health 不再报这个 |
| 没有 `action_required` | 没人能解（网络/结构性无源） | 只报 `absent_reason` | — |

> ❗ `dev_pin_selector` 找老板没用。那是配置的活，找错人会让老板白忙一轮。

## 3. 需要人时怎么办（措辞比命令重要）

### 3.1 zsxq 扫码（首次 / 会话过期）

见 §1.3 的模板。**会话过期的措辞要区别于首次**：

> "会话过期了，需要重新扫一次码——不是配置问题，站点会定期把网页端踢下线。"
>
> 同样只提一次，别下次采集又报就再催一遍。

**人回"扫过了"之后必须验证**，不能听信：

```bash
python -m pipelines health --class 03
```

| 结果 | 含义 | 下一步 |
|---|---|---|
| 变 `ok` | 通了 | 继续 |
| 还是 `no_session` | 没扫成功 | 按顺序问三句（一次只问一句）：窗口弹出来了吗 → 显示的是二维码还是「获取登录二维码」按钮 → 扫完页面跳转了吗 |
| 变 `confirm_account` | 登上了但 0 星球 | 走 §3.2 |
| 变 `selector_not_pinned` | 有星球但没钉版 | 你自己去钉（§1.5） |

### 3.2 "0 个星球"怎么说（最容易说错）

**禁止**：
- ❌ "知识星球没有数据"（听起来像源坏了）
- ❌ "星球采集失败"（失败了什么？没说清）
- ❌ "已覆盖知识星球"（明明什么都没采到）

**应该说**：

```
登录成功了（账号「<昵称>」），但**这个微信号名下没有加入任何星球**，
所以没有可采的内容——不是接口问题。

两种可能，你确认一下是哪种：
A) 要采的星球在另一个微信号下 → 用那个号重新扫一次码
B) 这个号还没加入 → 先在知识星球里加入目标星球，然后告诉我
```

依据是实测的三处一致：接口 `groups: []`、首页文案"还没有加入星球"、`expired_groups: []`。

### 3.3 ima 导出（每次都要人点）

你要给的三样东西，缺一样人就会做错：

1. **目标目录**（绝对路径，**先建好**再发请求）
2. **要哪些文件**——知道就列清单，不知道就说"这个知识库里的全部 PDF"
3. **一句话操作指引**——**不要让他读文档**，直接说：

```
请在 ima 客户端里：知识库 → 点开文件 → 右上角「下载」，
存到这个目录：<绝对路径>

（如果弹出保存框要求选目录：Windows 按 Alt+D 输路径回车；
 Mac 按 Cmd+Shift+G 输路径回车。文件名框只填文件名，别填整条路径。）
```

> 分平台的两行是**给人口述用的**，不是让人去查文档。
> 你自己要清楚：Windows 那句话本机实测有效；**Mac 的 `Cmd+Shift+G` 没有真机验证过**，
> 所以说完补一句"如果存不进去，直接存到「下载」文件夹，我来搬"。

**收到"已下载"之后**：

```bash
ls -la pipelines/_landing/ima/<日期>/
```

| 看到什么 | 含义 | 下一步 |
|---|---|---|
| 有 PDF | 正常 | 校验 `%PDF` 头 + `%%EOF` 尾 + 页数 > 0，报"收到 N 份" |
| 目录空 | 多半存到系统下载文件夹了 | 去 `~/Downloads`（Win 是 `%USERPROFILE%\Downloads`）搬过来 |
| 有 `.tmp` / 无扩展名 | 下载没完成 | 让人重下那一份，**不要拿半截文件当成品** |

校验不允许省：三条都过才算收到。

## 4. 防骚扰

判据：**同一个 `kind` + 同一个 `slug` 已经请求过、且人已经回过话**，就不再重复提。

- 不要每跑一次采集就催一次
- 不要把同一条请求同时发给多个人
- 不要用"紧急""必须马上"——它不是线上故障，是待办

---

## 5. 禁止清单

| ❌ 不许 | 为什么 |
|---|---|
| 自己用鼠标键盘去点客户端 GUI | 可能点错/误删；人机抢焦点时行为不可预测 |
| 改 `channels.yaml` / `t3_sources.yaml` 让报错消失 | 把"缺口"改成"假绿"，比缺口本身更糟 |
| 把 `unavailable` 写成"无风险 / 已覆盖" | 缺数据与没有风险是两回事 |
| 会话过期时反复重跑 `login` | 每次弹窗，人会被烦到关掉整个流程 |
| 把 `empty` 写成"没有材料" | `empty` = 查过确实没有；`没有材料` = 没查 |
| 让人读文档或敲命令 | 他只需要扫码，别的都是你的活 |

```
                                      │
                                      └─ unavailable ──→ 看 kind：
                                                            dev_pin_selector → 自己修
                                                            其它 → 转述 + 等回话 + 验证
```
