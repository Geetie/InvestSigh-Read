# 自动化管线与入库指导

> **一句话**：取数分两段落点——原件进 `pipelines/_landing/`（内部工作区，可重放），
> 可读材料进 `corpus/materials/`（产品数据，阅读器只认这里）。**落错地方 = 前端看不见**。

本文所有路径、字段、命令都在 2026-10-29 实机验证过。写的是**现状**，不是设想。

> **三份配套文档**：
> - 换机器 / 装依赖 / 挂定时 → `docs/部署与调度.md`（跨平台，不绑定任何 Agent 产品）
> - **T3 的一切**（初始化 / 登录引导 / 缺口分诊 / 话术）→ `docs/T3Agent引导.md`
>   （这是唯一一份 T3 文档；老板不看文档，他只扫码）

## 1. 两段落点（必须先分清）

| 段 | 路径 | 谁写 | 可变性 | 谁读 |
|---|---|---|---|---|
| **原件** | `pipelines/_landing/<source_id>/<as-of>/<artifact_id>__<hash12>.<ext>` | `_kit/land.py` | **只增不改**（同 hash 重跑记 `skipped`） | `_fetch_manifest.jsonl` 对账、重放 |
| **材料** | `corpus/materials/<material_id>/` | `_kit/material.py` | 同 id 内容变则整目录重写 | `server/store.mjs` → 阅读器前端 |

两段的职责不能混：

- `_landing/` 在 `.gitignore` 里（体积大、可重取）⇒ **它是工作区，不是交付物**。
- `corpus/materials/` 是仓库里的产品数据 ⇒ **它是唯一被阅读器消费的地方**。

一份材料完整走完是：`fetch`（拿到字节）→ `land`（原件落 `_landing`）→
`normalize`（转文本）→ `write_material`（落 `corpus/materials`）→ `append_manifest`（记账）。

> ⚠️ `_landing/` 被外部清理过（本次核查时它是空的，而 materials 有 389 份）。
> 后果不是"材料丢了"，而是**幂等键丢了**——重跑会把同一份原件再写一遍。
> 清理时**不要**用 `git clean -xdf` 连带删它，除非你确定不需要重放。

## 1.1 数据的实际流向（**PDF 与 HTML 不一样**）

拉下来的东西**同时落两处**，不是"先存 `_landing` 再搬进 materials"：

```
fetch 拿到字节（在内存里）
  ├─→ pipelines/_landing/<source>/<date>/<id>__<hash>.<ext>   原件留档（不可变、可重放、gitignore）
  └─→ normalize(内存里的同一份) → write_material → corpus/materials/<id>/   材料
```

`_landing` 是**副本**，入库走的是内存里那一份，从不从 `_landing` 读回。

### 但 materials 里装的东西，取决于载体

| 载体 | materials 里有什么 | 阅读器能直接读吗 |
|---|---|---|
| **HTML / CSV / JSON / XML**（01/02/03/04/05/06/07 的 23 个 auto 型） | `pages.json` 里是**真正文**分块 + `content.md` 全文 | ✅ 能，打开就是内容 |
| **PDF**（`03-broker-research`、`03-independent-research`、`03-expert-channel`） | `source.pdf` + **一份指针说明**（1 块）+ `meta.needsExtraction: true` | ❌ **不能**，正文还没抽 |

### 为什么 PDF 只给一个"壳"

PDF 抽正文必须经 `tools/pdf-pipeline`（远端 MinerU，要 GPU）。管道本身不抽，
所以只落"这是哪份文件、原件在哪、还需要抽取"的说明，并**显式标 `needsExtraction`**。

这样做的唯一目的：**不让下游把"有材料"误当成"可判读"**。
如果你在 materials 里看到 `pageCount: 1` 且正文是"来源与状态…待抽取"，
那就是还没过 MinerU，不能拿去判读。

### 检查一份材料是"真内容"还是"壳"

```bash
# 看这个字段就知道
python -c "import json;print(json.load(open('corpus/materials/<id>/meta.json'))['needsExtraction'])"
```

`true` = 壳，待抽取；`false` 或没有该字段 = 真内容。

## 2. `corpus/materials/<id>/` 的硬要求

必需三件 + 两个可选：

```
corpus/materials/<material_id>/
├── pages.json      必需   分块正文（阅读器 readSource 读它）
├── content.md      必需   全文（readContent 读它）
├── meta.json       必需   元信息（readMeta 读它）
├── source.<ext>    必需   原件副本：htm / pdf / csv / json
└── figures/        可选   抽出的图（许多型无图，空目录可不建）
```

`server/store.mjs` 只认这三个文件的**文件名**（`pages.json` / `content.md` / `meta.json`），
`figures/` 用 `listFigures()` 扫目录。**目录里没有 `pages.json` ⇒ 阅读器直接跳过这份材料**。

### pages.json

```json
{
  "id": "07-consensus-gap-2026-10-29-META-forecast",
  "srcId": "META-forecast",
  "pageCount": 6,
  "pageCaliber": "logical_block",
  "sourceSha256": "…",
  "pages": [
    {"n": 1, "text": "Stock Price Forecast\n\nAccording to 62 analysts…",
     "chars": 1180, "section": "Stock Price Forecast", "figures": []}
  ]
}
```

三条要点：

1. **`pages[].n` 是逻辑块号，不是 PDF 物理页**（`pageCaliber: "logical_block"`）。
   写"第 3 页"时指的是第 3 个块。PDF 材料走 `tools/pdf-pipeline` 才有物理页口径。
2. `chars` 可以用 `len(text)` 算，`section` 是块标题（无标题时用 `§N`）。
3. 手工材料（2026-10-28 之前的）用的是 `part` 字段而不是 `section`，
   `pages[].figures` 里放 `{"name","order"}`。**两种都能被阅读器读**，新代码统一用 `section`。

### meta.json 最小集合

```json
{"id":"…","cat":"07","sub":"consensus-gap","date":"2026-10-29",
 "pageCount":6,"figureCount":0,"figuresWithPage":0,"ordered":true,
 "pageCaliber":"logical_block","sourceSha256":"…",
 "source":"stockanalysis","provider":"…","url":"https://…"}
```

`sourcfe`/`provider`/`url`/`sourceSha256` 是**管线新增**的字段（历史手工材料没有），
它们让"这份材料从哪来"可追。**新写的 Adapter 必须填 `source` 与 `url`。**

## 3. `material_id` 规则（这里有个已知隐患）

格式：`{类码}-{子型}-{日期}-{主体}`，只含 `[0-9A-Za-z._-]`。

| 来源 | 日期取什么 | 例子 | 稳定性 |
|---|---|---|---|
| SEC 系（`sec_edgar`） | **文件自身日期** | `01-10-K-2026-01-29-meta20251231` | ✅ 稳定，重跑同 id |
| 其余绝大多数 Adapter | **运行日 `window.as_of`** | `07-consensus-gap-2026-10-29-META-statistics` | ❌ 每天一个新 id |

**后果**：`run --all` 每天会在 `corpus/materials/` 新增约 25–30 个目录，内容可能与昨天完全一样。
实测已存在 **9 组、21 份内容完全相同**的材料（`sourceSha256` 相同、id 不同），例如：

```
650ea0cf98be → 3 份
   03-consensus-ratings-2026-10-28-META-statistics
   04-short-option-2026-10-28-META-statistics
   07-consensus-gap-2026-10-28-META-statistics
```

三种成因要分开看：

1. **跨型共源**（上面的例子）：三个型都要 stockanalysis 的 statistics 页，各存一份。
   → 正确做法是**一个源只落一份**，其余型引用它（当前未实现，见 §7 待办 1）。
2. **同日跨型重复**（`01-8-K` / `01-other-forms` / `02-company-voice` / `05-chain-tracking` 同 hash）：
   多为联调时同一 URL 被多个型取到。
3. **跨日同内容**：`07-sentiment-survey` 这类序列，文件不变但 id 每天变。

> 现状**不影响阅读**（每份都完整可读），影响的是**入库卫生**与目录增长速度。
> 在改幂等键之前，建议按 §5 的体检命令定期看一眼重复组数。

## 4. 34 型的入库形态

| status | 型数 | 是否进 `corpus/materials` | 说明 |
|---|---|---|---|
| `auto` | 19 | ✅ 全自动 | 跑完即有材料 |
| `partial` | 4 | ✅ 但只覆盖源的一部分 | `channels.yaml::partial_note` 写明缺什么 |
| `needs_key` | 1 | ⏸ 有 key 才进 | 缺 key 时 `unavailable(no_api_key)`，**不是失败** |
| `t3` | 3 | ❌ **只到 `_landing`** | 见 §6，需人工/GUI；PDF 需 MinerU 才能进 materials |
| `map` | 6 | — | 查表册，不取数 |
| `unavailable` | 1 | — | 结构性无源（`07-prediction-market`） |

**关键区别**：`t3` 型取到的是 **PDF 原件**，`write_material` 只写"原件指针材料"
（`source.pdf` + 一份说明正文，`needsExtraction: true`），**不能直接判读**。
要变成可读材料必须过 `tools/pdf-pipeline`（远端 MinerU）。

## 5. 验收命令（改完代码就按这个顺序跑）

```bash
# ① 静态守卫：34 型全覆盖、Adapter 齐、13 字段 manifest、T3 越界检查
python -m pipelines selftest           # 必须「全绿」

# ② 离线契约测试（不联网）
python -m pytest pipelines/tests -q
#   期望 38 passed。
#   若报 "No module named pytest"，说明当前解释器没装 pytest——
#   换一个装了它的解释器，或 `python -m pip install pytest`；不要在仓库里建 venv 绕过。

# ③ 可达性（不落材料）：今天哪些源能用
python -m pipelines health --class 03

# ④ 单型实跑（先小范围，别一上来 --all）
python -m pipelines run --type consensus-gap --as-of 2026-10-29 --dry-run   # 只落原件
python -m pipelines run --type consensus-gap --as-of 2026-10-29            # 落原件 + 入库

# ⑤ 入库体检（只读，不改任何东西）
python -m pipelines audit              # A1 缺件 / A2 空页 / A3 零字 / A4 重复 / A5 缺来源
python -m pipelines audit --root <别的材料根>   # 也可指向测试用 fixture
```

`audit` 的退出码只有两种：`0` 全过、`1` 有违例（逐条具名，格式 `[A4] 内容重复(hash) N 份: id…`）。
五条判据都做过阳性对照（造反例确认能抓到），**不会出现"永远通过"的假绿**。

`--dry-run` 的语义是**只 fetch + land，不写 materials**——用它验证"源通不通"，
不要用它验证"入库对不对"。

单个型的产出必须能对上三处：

```bash
ls pipelines/_landing/stockanalysis/2026-10-29/          # 原件 + _fetch_manifest.jsonl
ls corpus/materials/07-consensus-gap-2026-10-29-META-*/  # 4 个文件
python -m pipelines status --type consensus-gap --as-of 2026-10-29
```

## 6. T3（已购库）：zsxq 走 API，ima 走 GUI

### 6.1 落点约定

T3 的原件**一律落** `pipelines/_landing/ima/<as-of>/` 或 `pipelines/_landing/zsxq/<as-of>/`，
**不要**直接往 `corpus/materials/` 塞 PDF——那样它没有 `pages.json`，阅读器会当它不存在。

### 6.2 zsxq（知识星球）：等账号

- 登录：`python -m pipelines login --source zsxq`（微信扫码，会话落 `_profiles/zsxq.state.json`）
- 判据：`/v2/groups` 未登录 401 / 登录 200（已四次阴性对照）
- **当前卡点**：登录账号「无霜」名下 0 个星球 ⇒ `group_ids` 为空 ⇒ `no_target_configured`
- 有星球后：从 `/v2/groups` 的 `resp_data.groups[].group_id` 取 id 填 `t3_sources.yaml`，
  再按真实 DOM 钉 `item_selector`

### 6.3 ima（腾讯）：只有 GUI 一条路

web 端没有知识库视图、客户端没有程序化入口（八条路已逐条排除，见
`t3_sources.yaml::ima.probed`）。**只能靠 UI 自动化**，已验证可行的完整流程：

```
① 单击 PDF → ima 打开预览窗口（独立 hwnd，标题=文件名）
② 点工具栏「下载」→ 弹「另存为」
③ Alt+D 聚焦地址栏 → 粘贴目标目录 → 回车（必须先导航进目录！）
④ 文件名框只填纯文件名 → 回车
⑤ 校验：sha256 与源一致、pymupdf 能开、页数对得上
```

**三个必须知道的坑**（都实测踩过）：

| 坑 | 现象 | 正解 |
|---|---|---|
| 旧 API `mouse_event` | 点了完全没反应，UI 无变化 | 用 **`SendInput`**（Chromium/Electron 只认真实输入） |
| DPI 混用 | 坐标总是偏 | 统一物理像素：`SetProcessDpiAwareness(2)` 后 GetWindowRect / PrintWindow / SetCursorPos 三者一致 |
| 文件名框塞路径 | 报「**文件名无效**」或存到 Downloads | 文件名框**只填文件名**；目录必须经**地址栏**导航 |

`batch` 批量时还要注意：每份 PDF 会在**同一个预览窗口里新开标签页**，
连续点会堆积标签，需要在每次下载后关掉当前标签。

### 6.4 半自动兜底

如果 GUI 自动化跑不稳，退化方案是：人工在客户端点下载 → 文件落系统默认下载目录
（macOS/Linux `~/Downloads`，Windows `%USERPROFILE%\Downloads`）
→ 由脚本按 `_landing/ima/<as-of>/` 规范归档（重命名成 `<artifact_id>__<hash12>.pdf`）。
这条路径**不依赖任何 UI 操作**，只是需要人工点一下"下载"。

> ima 的 `Preferences` 里**没有 download 配置**，所以下载目录固定是系统默认。

## 7. 已知问题清单（按优先级）

| # | 问题 | 影响 | 处置 |
|---|---|---|---|
| 1 | 多型各自落同一份共源数据（9 组 21 份） | 目录膨胀、统计口径混乱 | **待改**：`write_material` 前先用 `sourceSha256` 查重，命中则只记 alias |
| 2 | `material_id` 含运行日 | 每天 +25~30 目录 | **待改**：改用内容 hash 或数据自身日期做幂等键 |
| 3 | 305 份历史材料无 `sourceSha256` | 无法参与去重 | 不动；只要求**新产出**必须带 |
| 4 | `_landing/` 被外部清理过 | 幂等键失效、原件重写 | 清理时排除该目录 |
| 5 | `source` 命名两套：`sec-edgar` / `sec.edgar` | 按源统计时会被拆成两组 | 历史不动；新代码统一 `sec.edgar` |

第 1、2 条是同一个根因（**幂等键选错**）的两个表现，一起改比分开改省事。
