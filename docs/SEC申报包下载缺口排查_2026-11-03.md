# SEC 申报包下载缺口排查与修复（2026-11-03）

> 起因：Meta 2026-10-26 融资 8-K 的全部绑定条款附件（承销协议、指定证书、远期确认书）从未进语料，
> 四张阅读卡只能基于正文摘要填写。用户判定：**采集器不应主动裁剪，申报包内申报文件全部需要**。
> 本文记录排查证据、修复内容与遗留决策。

## 一、原采集逻辑（问题所在）

`pipelines/01-监管一手披露/sec_edgar.py`（01 全部 6 型 + 02 company-voice/cross-read + 05 chain-tracking 共用）：

- **只取主文档**：10-K / 10-Q / 委托书 / 招股书 / 其他条目与红灯；
- **8-K 例外**：`include_exhibits` 开启时，按 `_EXHIBIT_PATTERNS`（仅 `ex991` 系 5 个模式）挑 EX-99.x；
- 两个直接后果：
  1. **一切 EX-10.x / 3.x / 4.x / 5.x 附件永远不落盘**——绑定条款只在附件全文里，正文摘要依法"不意图完整"；
  2. **配置与代码脱节**：`channels.yaml` 写 `include_exhibits: ["EX-99.1","EX-99.2"]`，但模式表只匹配 991，
     **EX-99.2 实际永远抓不到**（旧版采集器 2025-12 还抓到过 `dec122025exhibit992`，现行代码匹配不上）。

## 三、修复内容（已实施，测试 38/38 绿）

1. **`sec_edgar.py`**：
   - `_exhibit_names`（白名单模式）→ **`_package_documents`**（全包模式）；
   - 对**所有表单**生效（去掉 `include_exhibits` 开关——不裁剪不需要开关）；
   - 排除项只有机器渲染物与冗余件（**不是内容裁剪**）：`R*.htm`（XBRL 渲染视图，10-K 包 91 个）、
     `FilingSummary.xml` 与 `*_lab/_cal/_def/_pre/_htm.xml`（XBRL 机器件）、`<accession>.txt`（全包串联件）、
     index 页、带目录前缀渲染壳；申报文件判定 `.htm/.html/.txt`；
   - 单附件请求失败不停整包（主文档已到手，缺件按"附件未在手"处理）。
2. **`channels.yaml`**（01-8k、02-company-voice）：删除 `include_exhibits`，写入新口径注释。
3. **干跑验证**：用 8 个真实包的 index.json 跑新筛选——选中清单与上表"缺"列逐一吻合，91 个 R 渲染件全部排除。
