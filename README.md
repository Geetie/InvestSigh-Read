## 零、这一份是「前端空壳」，后端另配

本目录 = `dashboard-swiss` 的完整前端壳子，搬进来是为了接后端。改动只有一处：
**所有数据访问收到 `src/lib/api.ts` 一个文件里**，页面里不再有 `fetch("/data/…")` 或 `localStorage`。

```bash
npm run server       # 后端，127.0.0.1:5280（零依赖，Node 原生 http + 文件存储）
npm run dev          # 前端，127.0.0.1:5277（vite 已把 /api 代理到 5280）
npm run seed         # 一次性：把 public/data/bundle.json 搬成 server/data/materials/*.md
```

`.env.local` 里有 `VITE_API_BASE=/api` 就连后端；删掉这一行即回退 mock（读 public/data + localStorage），
后端挂了前端也还能跑。实测首页只发 **3 个请求**：`/taxonomy`、`/materials`、`/prompts?date=`。

| 需要联调的页面 | 走后端的东西 |
|---|---|
| 日看板 / 时分矩阵 / 详情页 | 类与型的清单、材料列表（含每行答案）、原文分页 |
| 提示词编辑 | 某型某日生效的问题与读法；保存一版 |

产业链三页是静态结构，不联网。

**完整契约在 [`docs/CONTRACT.md`](docs/CONTRACT.md)**：五个端点、payload、MD 模板的解析规则、
以及那条最容易做错的规矩 —— **模板由提示词版本生成，不许手写第二份**（手写必然漂移，
最后出现「界面问 A、agent 答 B」）。生成器：`node tools/gen_template.mjs --sub chain-tracking --version 1`，
样例产物在 `templates/chain-tracking.v1.md`。

### 目录

```
corpus/                     ← 输入区（人维护）
  prompts/<NN>-型/<册>.md    ← 判读手册（唯一真相源：问句表 + 读法 + 判据），34 册
  templates/<类>-<册>.md     ← 采集登记表模板（33 份），agent 复制到 output/<标的>/<材料 id>/
  materials/<材料 id>/        ← 一份材料一个目录（见下「三处落点」，旧 raw/ + mineru/ 两层已合并）
output/                     ← 产出区（agent 写、后端读）按标的分两级
  <标的>/<材料 id>/material.md   ← 一个标的下一份材料一个文件夹
server/index.mjs            ← 后端：8 个路由，零依赖
server/parse-md.mjs         ← MD → Material（frontmatter + `## id · 问题` + `### 依据`）
server/template.mjs         ← 提示词版本 → MD 模板
server/store.mjs            ← 文件存储（corpus / output 两棵树）
server/regen-templates.mjs  ← 用 index.json 重出全部模板
server/seed.mjs             ← 一次性迁移：bundle → output/
src/lib/api.ts              ← 唯一接缝：mock / http 双实现
src/lib/prompts.ts          ← 提示词门面（同步取行 + 异步同步/保存）
src/lib/prompts.local.ts    ← 本地缓存（mock 时是库，http 时是读缓存）
docs/CONTRACT.md            ← 前后端契约 + MD 模板规范
pipelines/                  ← 材料获取管道（只采美股；7 类 34 型；CLI 工具，**不含调度器**）
  SKILL.md                  ← ★ 给 Agent 的操作手册（何时跑、怎么读报告、三态处置）
  _kit/                     ← 五段骨架 / 三态 / 13 字段 manifest / 落盘 / 浏览器会话（唯一实现）
  _keys/                    ← B 类免费 key 的申请步骤 + check_keys.py（不存密钥）
  <NN>-<类名>/               ← 每类一个文件夹：channels.yaml（型声明）+ <adapter>.py
```

### 一份材料在磁盘上的三处落点

```
corpus/materials/<材料 id>/source.pdf|.htm      ← 原始件（管道或人放进来）
corpus/materials/<材料 id>/{content.md,pages.json,meta.json,figures/}   ← 可判读形态
output/<标的>/<材料 id>/material.md             ← agent 成品（答题卡填完）
```

三处用同一个 id 串起来（成品那处多一层标的目录）。
取材料的两条路：**自动**（`python -m pipelines run --class 01`，见 `pipelines/SKILL.md`）
或**人工投递**（往 `corpus/materials/<id>/` 放原件 → 跑 MinerU → `tools/pdf-pipeline/`）；
之后都是 agent 复制模板到 `output/<标的>/<材料 id>/` 再填。

### 1.3 答案分段高亮（仅详情页）

**用途是「把一段长答案切开」，不是标词性。** 一句归一类，优先级 结论 > 数据 > 限定，
所以一格里最多出现三种底色、且不会互相嵌套。

色板取 **Radix Colors**（专为 UI 设计的 12 阶色板）：底色用 step-4（UI 元素背景，白底上够区分又不刺眼），
行首短杠用 step-9（实色）。

| 档 | 底色(step-4) | 短杠(step-9) | 判定 |
|---|---|---|---|
| 结论 | `#ffecbc` amber4 | `#ffb224` amber9 | 首句（切到第一个 `。`/`；`/`[p.N]`） |
| 数据 | `#e1f0ff` blue4 | `#0090ff` blue9 | 含数字 + 量纲 |
| 限定 | `#ffe8d7` orange4 | `#f76808` orange9 | 但/仅/约/未披露/无法核实… |
| 出处 | `#f3f3f3` gray3 芯片 | — | `[p.N]` 页码，不是高亮档 |

### 1.4 字体 / 圆角 / 新拟态

- 拉丁 `Inter Tight`（自托管 variable）· 数字 `IBM Plex Mono` · 中文系统栈 · 英文原文 `Georgia`
- **圆角只属于能被按下去的东西**：版面 0、卡片 0、软控件 10px、AI 球 50%
- 新拟态只用 4 条阴影 token，只出现在 6 个控件上（AI 球、输入框、粒度切换、滑杆、返回键、图例）
- 阴影用**暖棕** `rgba(38,33,26,.10)`，底色用暖纸灰 `#F4F3EF` —— 不是经典蓝灰新拟态

### 1.5 工艺层：极简 ≠ 草率

找组件库的时候要认清一件事：**没有哪个库能给你瑞士风**（shadcn 的 `Lyra` 风格最接近，
「boxy / sharp / 适合配等宽字体」，但它给的是形状，不是纪律）。纪律是一张核对表，
下面这张来自 Swiss Modern 的设计系统规范，逐条对本项目成立：

| 判据 | 我们的做法 |
|---|---|
| 边框不超过 1px | 全站发丝线 `--color-rule`，只有「章节线」用 2px 墨 |
| 硬偏移阴影 = 新野蛮主义 | 不出现 `2px 2px 0` 这类偏移影 |
| 字体家族 ≤ 2 | Inter Tight + IBM Plex Mono（等宽仅用于编号/元数据） |
| 文档必有 40% 以上留白 | 版面按列宽收，空白是计算出来的，不是没填满 |
| 标签：小、大写、字距放开 | `9.5px / tracking .18em / ink-300`，全站统一 |
| 正文 65–68ch 阅读宽度 | 读法、原文、注释一律 `max-w-[68ch]` |
| 层级靠字号字重，不靠颜色 | 只用 `ink-900/700/500/400/300` 五级墨 |

**补齐的四件小事**（写在 `index.css` 末尾的 craft layer，缺了它们页面就还是「极简但不精致」）：

1. `::selection` 改成墨底纸字 —— 浏览器默认的蓝色选区会瞬间打穿黑白体系；
2. `:focus-visible` 给所有非输入类控件加 2px 硬边圈（输入框靠边框变墨，不重复加圈）；
3. 滚动条压到 9px、槽透明 —— Windows 默认滚动条是页面上最不设计的一处；
4. 台账型数字一律 `tnum`（等宽数字），否则时间轴与计数会一跳一格。

### 1.6 动效来源：只从一处取，并且只取编码了「真事」的那几个

把 React 生态的视觉库逐个翻过一遍（ReactBits 免费库 220 个 / Motion Primitives 47 个 /
Magic UI 150+ / Aceternity / Kokonut / Cult UI / Origin UI / shadcn 各 registry / 21st.dev）。
**结论不是「多装几个」，而是「同源」**：21st.dev 自己那篇文章说得最准 ——
从六个库各拿一个效果，页面会出现六条不同的缓动曲线，最后看起来是拼的，不是设计的。
所以本项目只从 ReactBits 取件（它统一用 rAF + 弹簧/指数平滑），而且只取**编码了真实含义**的四个：

| 组件 | 用在哪 | 它编码的是什么事 |
|---|---|---|
| `MagicBento` | 产业链节点卡 | 光标靠近 → 那一格被照亮（空间关系） |
| `LineSidebar` | 提示词页的条目索引 | 光标靠近哪一行 → 哪一行先亮（就近感） |
| `Magnet` | 保存按钮 / 提示词入口 | 按钮是实体，靠近会被吸住 3–4px（可点） |
| `ProfileCard` | 产业链选择页 | 卡片可被拿起看（3D 倾斜 + 全息箔） |

**明确否掉的**（不是不好，是不属于这套语言）：
Backgrounds 全部 66 个（光、粒子、WebGL 流体 —— 白纸上没有光）、
Text Animations 里的 Glitch / Scramble / Particle / Warp（噪音大于信息）、
Cursor 类全部（改变系统指针的形态，是侵入）、
Dock / GooeyNav / PillNav 这类拟物导航、以及所有 `span 2×2` 的营销 bento。

> 判断标准只有一条：**这个动效在回答哪一个真实的问题？** 答不上来的，再漂亮也不用。

## 四点五、第 0 层：产业链

路由在四层之前插了一层，现在整条链路是：

```
#/chain          产业链选择（三张卡）
#/chain/:id      某条链：环节列 × 企业落位
（无 hash）       七类阅读器：类 → 型 → 材料(日/矩阵)
#/m/…/…          详情页：答案 + 原文依据
```

三条链是**平级的三个视图**，不是三级路径：链页顶部那个名字本身就是下拉，
就地切换到另外两条，不必退回选择页。返回入口只留图标（方框 + 墨线悬停），不再写字。

**选择页**（`ChainPicker`）：三张 **React Bits `ProfileCard`**（`src/components/vendor/ProfileCard.jsx` + `.css`）。

| 项 | 说明 |
|---|---|
| 依赖 | `@hugeicons/react` `@hugeicons/core-free-icons` |
| 保留 | 指针驱动的 3D 倾斜（弹簧积分）、视差、全息箔、glare、`prefers-reduced-motion` 降级 |
| 改动 | ① 默认值清空（不传不会冒出 Javi A. Torres）② footer 去掉 `@` ③「联系」→「进入」+ 右箭头 ④ 默认 light 主题、默认关闭 intro ⑤ 加 `.chain-xl` 宽 356px ⑥ 未开的链加 `.profile-card--idle` 降饱和 |
| 配图 | ImageGen 生成 3 张黑白工业摄影（数据中心 / 公路 / 关节），压到 480×600 放在 `public/chain/` |

> **「零光效」的准确含义**：禁的是**霓虹发光类**——`box-shadow` 彩色辉光、`text-shadow` 辉光、
> 光柱/流光/扫描线/CRT/色差/粒子，以及赛博语境下的 `blur` 光斑。
> **不算光效**：毛玻璃（`backdrop-filter`）、投影、全息箔、3D 倾斜、渐变遮罩——这些是材质与体积，
> 不是「灯在发光」。所以 ProfileCard 合规，不构成例外。

**链页**（`ChainMap`）：**dagre **横向**分层 DAG + 白纸风格 + 全链通路提亮**。

> 中途走过一段弯路：照搬了参考仓库（neural-creator-dashboard）的暗色星图 —— 中心光球 + 环绕节点 + 触须。
> 那套是「创作图谱」的表达（模块与内容是并列关系），而产业链是**有方向的层级**：
> 上游喂下游、多输入汇合。中心辐射会把上下游压平成一个平面，结构信息就丢了。
> 所以撤掉，只借它的**交互模型**，不借皮肤。

**为什么横着放**：产业链就是「谁供给谁」的单向流，从左到右是这类图的天然阅读方向
（供应链画法的通行约定：供应商在左、终端在右，横向排布还顺带把顶部让给层级标尺）。
竖排会把 7 个层级拉成一条 3000px 的长条，读者永远看不到全貌。

**顶部标尺**：整张图上方挂一条**三等分**的连续色带，标「上游 / 中游 / 下游」。

这里出过一次错：第一版是按「列的归属」分组的，7 列只能切成 2/2/3 —— 下游那一段宽出 50%，
看上去就像没对齐。现在改成**按宽度三等分**：三段永远一样宽，标签居中，界标是两道短线。
它是刻度，不是分组框；分界线只存在于顶部 26px 的标尺里，不贯穿图面，所以不会切到卡片。
「某个环节属于哪一段」由列位置单独算（`bandOf(col)`），只影响选中时标尺那一段的墨色。

**产业链自己的信息在「上下游」**：点任一环节时，沿边的方向做**传递闭包** ——
全部上游祖先 + 全部下游子孙 + 它们之间的连线一起提亮，其余压到 26%。
只有落在「该环节 → 源头 / 该环节 → 终端」主通路上的边才转黑加粗，
同属闭包但不在这条通路上的边保持浅灰。这一步比任何特效都更能说明结构。

| 项 | 做法 |
|---|---|
| 布局 | `@dagrejs/dagre`，`rankdir: LR`，`nodesep 22 / ranksep 56`，列宽 190 |
| 层级 | 最长路径（`rank(下游) = max(rank(上游) + 1)`）算语义层，位置交给 dagre；显示层号用 **dagre 的列号**，保证和列位置一致 |
| 对齐 | 同列节点**左边对齐**（宽度统一，等价于把 x 拉到该列最小值） |
| 连线 | 正交折线 + 10px 圆角，`from 右缘中点 → 水平右 → 垂直移 → 水平右 → to 左缘中点` |
| 卡片 | 头部固定 104px（编号/层号 + 上市刻度 + 环节名 + 释义 + 产出），企业行固定 28px（`ticker 名称` 单行） |
| 右侧面板 | **默认收起**（横向布局里宽度是稀缺资源）；**只讲环节**，标的不再开第二层 |
| 缩放 | 默认 **100%**，可切「适应一屏」。**绝不为了塞进一屏把字号缩到 12px 以下** —— 机器人链 5 路 fan-in 那列天生很高，滚比缩好 |
| 未上市 | 灰字 `未上市` + 灰名；点得亮环节，但点不进材料层 |

**卡片是「一块面 + 两种命中」**（这条改过两版，第一版做成两步点击是错的）：

1. 点卡片上**除公司行以外的任何地方** → 选中这个环节（提亮全链通路 + 右侧出环节详情）；
2. 点**某一行票** → **一下就走**，直接跳七类材料 `/?ticker=…&cat=05&sub=chain-tracking`。
   不要在链页再弹一层标的详情 —— 标的的阅读属于阅读链路，不属于图谱；
3. 退出 → 点画布空白，或 `Esc`。未上市的行点了只是把环节选上（没有披露可读）。

落地页也做了配套：`?ticker=` 现在会**真的过滤**该型的材料（原先只是顶栏挂个名字，等于没跳）；
这一型下没有这家的材料时，退回全部并显式打出 `no cover` 条，不许静默空屏。

**卡片外壳用 React Bits 的 MagicBento**（`components/vendor/MagicBento.*`，与上游逐字节一致）：
一个节点一个实例（`columns=1`），位置仍是 dagre 给的绝对坐标 —— 这样既拿到它那套
「指针 → 光」的物理，又不放弃 DAG 布局。所有改造都写在 `index.css` 的 `.chain-node` 段：

- **光照颜色换成琥珀 `#ffb224`**。白底 + 白卡时墨色的光等于没有（alpha 0.09 只到 `#f7f6f5`），
  实测完全看不出来；换成灯光色之后才像「一盏灯照过来」。
- **光晕半径压到 62px**。卡片只有 190 宽，240px 的半径会把整张卡均匀涂成一块奶油色，
  读起来像污渍不像光；小半径才有可见的衰减。
- **选中用 2px 墨线，不用光**。悬停时让边缘自行发亮，不再额外压一圈墨线去盖住它。
- 圆角 10、共享库沿用 `MagicBento.css` 原文件；焦点圈用硬边而非它默认的柔光。

**五个踩过的坑**（写在这里省一次返工）：

1. **新增依赖后必须重启 Vite**（`--force`）。`@dagrejs/dagre`、`@hugeicons/*` 装完不重启，
   页面白屏、`/node_modules/.vite/deps/*` 404。
2. **同列对齐的分组键必须是 dagre 返回的坐标**，不能是自己算的 rank；两者层数不一定一致，
   拿错的键分组会把不同列的节点拽到同一位置、叠成一团。
3. **`HEAD_H` / `CO_H` 必须等于真实渲染高度**（头部 104、企业行 28），填小了节点算矮、下层会压上来。
   判据不能靠目测：量 `button.scrollHeight > clientHeight`，被裁的环节会自己报出来。
4. **横向布局下宽度是真约束**。7 列 × 190 + 6 × 56 ≈ 1730px，1920 屏刚好放下；
   一旦把卡片放宽到 216，最右一列就被裁在视口外 —— 终端的「应用层」看不见，图就断了。
   同理，卡片里每加一行就多 12px，12 张卡会把「刚好放得下」顶掉；刻度行最后是塞进
   头部那行的右侧，而不是单独占一行。
5. **`--mb-shadow` 之类变量不能传 `undefined`**。MagicBento 把 `...style` 放在 `THEMES` 之后覆盖，
   React 会跳过 `undefined` 的键 —— 结果是连默认值一起丢掉，卡片变成没有阴影的方块。

## 四点六、提示词：只能改问题与读法（`#/prompts`）

这是阅读器，不是流程工具，所以这一块**刻意做小**。

**能改的只有两个字段**：每一条问题的措辞、以及这条问题的**读法**（该怎么读、允许用什么证据、
材料没写时怎么办）。不加行、不删行、不换行的类型、不排序 —— 行的结构是产品的一部分，
界面上不给动的入口。没有草稿箱、没有 diff 面板、没有回滚按钮。

**唯一的机制是「按生效日分版本」**，因为这是版本隔离的全部要求：

- 保存 → 从今天起生成（或覆盖当天）一版；
- 矩阵与详情页按**那一份材料的日期**解析版本：`生效日 ≤ 材料日` 里最新的一版；
- 于是旧材料永远解析到旧版，旧问题与旧答案原样成对，不会被新版本回溯改写。

> 为什么必须这样：答案是按行 id 存在材料上的（`cells[rowId]`），材料本身不可变。
> 若把新问题写到旧日期上，那些答案就会顶着新标题出现 —— 等于篡改历史。

| 位置 | 行为 |
|---|---|
| `lib/prompts.ts` | localStorage 一册 `{ subId: [{ at, rows }] }`；`rowsAt/versionAt/readingOf` 三个查询 + `savePrompt` 一个写入，就这些 |
| 入口 | **小类型栏右端的黑按钮「提示词」**（钉住不随标签滚动）。之前塞在矩阵上方一条细带里，等于藏起来 |
| 编辑页 `#/prompts/:subId` | 两栏：型标签 → 条目索引（Q1…Q12，改过的打红点）→ **一张居中的文档页**。中间那块是设计主体：问题当 40px 大标题排、一条 2px 墨线切开、读法当 18px/1.85 的正文排（62ch 阅读宽），可编辑性只用「页边记号」表达 —— 悬停/聚焦时左侧浮出 2px 竖线，不加框 |
| 矩阵页 | 顶部一条 `PROMPT 第 N 版 · 生效日 · N 问`；若该日落后于最新版，用强调色提示「该日仍用旧版」 |
| 详情页 | 大标题下面挂一行「读法」，让人看见这条答案是按什么规矩读出来的 |
