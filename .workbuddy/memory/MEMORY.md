# InvestSigh-Read · 项目长期约定

## 布局（只有这三处是真源）

- `corpus/materials/<材料 id>/`：一份一目录，`pages.json`（`{"pages":[{"n":1,"text":"…"}]}`，**n 是逻辑块号不是 PDF 页**）、`content.md`（图片按阅读顺序内联）、`figures/`、`source.htm`、`meta.json`。旧 `materials/raw/`、`materials/mineru/` 已废。
- `corpus/prompts/<NN>-型/<型>.md`：**判读手册 = 唯一真源**（§3 必过项、§4 问句表、§5 坑、§6 红灯）。
- `output/<标的>/<材料 id>/material.md`：成品。阅读器矩阵的行 = 手册 §4 问句表的 `Q1..Qn`，不是模板的 `S00..Snn`。

## 两个模板体系，别搞混

| 用途 | 文件 | 长相 |
|---|---|---|
| 阅读器单元格 | `output/.../material.md` | `## Q1 · 题面` + 答案 + `### 依据`（`- p.N｜原文片段`） |
| 批跑报告 | `corpus/templates/<类>-<册>.md` | `## Sxx` + 页码范围/登记/档位 |

照 `corpus/templates` 的 S 段写 `output` 的 material.md ⇒ 矩阵全空。S 段标题还必须带 `·` 才会被 `server/parse-md.mjs` 认出。

## check.mjs 的真实观测面

只查两件：R1 有答案必须有块；R2 块须逐字（去空白后子串）、页码不越界。

**盲区：空答案不触发任何规则** ⇒ 全新骨架也是「合格 · 无答案 · 0 块原文」。
所以判完成必须看那行有没有「N 行有答案」，并按作业书要求的行数对账。否定性结论前先做阳性对照（捏一条假引文必报 unverified）。

## 引用纪律

- 逐字抄，含 `&#160;` `&#8201;` `&#8222;` 等实体、`\$`、`&#9744;`；改一个字符即 unverified。
- 数字常被拆行（`$` 与 `51,242` 分行），校验去空白，所以依据行内用空格连起来即可。
- **Item 编号在 8-K 里常写成 `Item&#8201;8.01`**（窄空格实体），用正则 `/Item[^\d]{0,12}\d\.\d\d/` 找，字面搜会误判"无此条目"。
- 正文不写页码；「未见」三段式；「材料未给出此项」也要登 1–2 条范围证据（Item 行/附件清单），但别把同一张长表在六题里重复。

## 多 agent 填写的五条硬经验

1. **「答案比依据丰富」是 check 的盲区**：它只验"登记了的都真"，不验"真的都登记了"（`validate.mjs` 第 8 行自陈）。所以填完必须再跑一轮**专补登记**，否则答案里的数字读者在依据区找不到。判据：答案里每个来自本份的数字/专名，依据区都该有一条能支撑它的块；跨份对照的数字**不许**补块（那份查无此文，会 unverified）。
2. **数字探针要先做单位归一**：答案写「170 亿」而依据是 `17 billion parameters`，字符串比对必然假警报。不归一就跑，会把换算噪声当成缺依据（实测 31 处里绝大多数是噪声）。
3. **判读前先验输入**：`pages.json` 可能整份空（0 页）或只剩 7%–39%（`known_defects.json` 里 `extract_failed_retryable`）。对账口径 = `pages.json` 字符数 / `pymupdf` 文本层字符数；<85% 就别判，先用文本层重建（保留 `figures`、同步 `meta.json.pageCount` 与骨架 `source_pages`）。整页长截图型 PDF 文本完整但只有 1 页，全篇只能 p.1。
4. **check 之外还要一道门禁**：`tools/gate-03-media.mjs` 查页数对账、每格 ≥80 字、裸「未见」、正文页码、裸题号、跨行复用同一段原文。改脚本后先拿空骨架做阳性对照。
5. **措辞级错 check 一定漏**：本批抓到 4 处 —— 把 `one/another/third/fourth person` 数成“四组”、写“没有 8-K/WARN”（断言客观世界无此物，应写“本篇未引”）、“手头没有定期报告”（仓里其实有）、归因次数中英相加多算。数信源、说“没有”的句子，必须逐条回原文数。

## 02 类专属坑

- 手册 §4 首列必须是 `Q1..Qn`：`pass` 给 `renderTemplate` 的 `row.id` 直接当标题，写成 `1..4` 会出 `## 1 ·`。
- `renderTemplate` 的 `<在此填写答案…>` 占位符**不会被 `PLACEHOLDER` 过滤**（那只管 frontmatter 与依据区）⇒ 骨架一生成就显示「4 行有答案」。生成后必须删掉占位行。
- 材料 id 里的 `02-cross-read-2026-…` 不能用 `split('-')` 取日期，会得到 `read-2026`；一律从 `meta.json.date` 取。
- 入库注记（`competitor_class:`、`> 本份全文未提及 Meta`、`retrieval: web_fetch 摘要级`）是**我们自己写的**，当依据＝循环论证。载体限制写进答案正文，不进依据区。

## 03-独立研究 专属坑

- **交付物类型按内容判，不看文件名后缀**：`2025-11-07-ClusterMAX2`（无后缀、看着像 original）正文实为「英文段 + 中文译段」逐段对照 ⇒ 是 `bilingual`；`0000-00-00-…bilingual` 反而可能是重排版。Q3 必须给判断依据（页首是否并列两语、是否只有 `KEY POINTS`、正文是否压成条目），并点名同源组。
- **同源组先行**：本批 41 组里有 8 组是「英文原本已填、中文件待填」。中文件可打开已填的兄弟件对齐事实与写法，但**依据只能逐字来自自己那份**；中英数字不一致时以自己那份为准并注明「译本与英文原本不一致」（实测抓到「1,200 亿译成 120 亿」「超过两者各自写成超过两家之和」）。
- **`PAID` 是付费墙不是投行关系**：Q7 三项（收费顾问 / 投行关系 / 持仓或受资助）在独立研究里几乎恒为「未声明」，但必须先查文末 Disclosure、作者简介、`sales@` 招揽、评论框，再写三段式；拿 PAID 反证「无投行关系」= 一票降级。
- **骨架 `source_pages` 会与 `meta.json.pageCount` 不一致**（本批 8 份，全是声明值偏小）⇒ 后面的页引用全被 check 判越界、agent 只敢引前几页，摘要件尤其吃亏（1 页声明挡住第 2 页条目 5—8）。开工前先对账并改正，再让人填。
