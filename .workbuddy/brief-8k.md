# 8-K / EX-99.1 填卡作业书（本批 20 份 · 唯一作业规范）

> 你负责**一份**材料。这份作业书是硬规范，照做，不要自己发挥格式。
> 判据真源是仓库里的 `corpus/prompts/01-型/8-K与EX-99.1.md`，本作业书是它的执行版；两者冲突时以手册为准。

## 0. 你的输入输出

- 输入：`corpus/materials/<材料 id>/pages.json`（`{"pages":[{"n":1,"text":"…"}]}`，`n` 就是依据区要写的 `p.N`）、同目录 `content.md`（同内容，图片按阅读顺序内联）。
- 输出：`output/meta/<材料 id>/material.md` —— **骨架已经生成好**，你只填 8 个 `## Qn` 段下面的答案正文与 `### 依据`。

**不许做的事**：
- 不改 frontmatter（`---` 之间那 12 行）。
- 不改、不删、不新增 `## Qn · …` 标题；问题文字一字不动。
- 不新增小节、不加 `####`、不写「回执」「覆盖」「自检」这类机器账。
- 不建别的文件，不改别的材料。

## 1. 先读完，再动笔（不许跳读）

0. **怎么把长文读出来**：`pages.json` 是一行行的 JSON，`text` 里是 `\n` 转义，直接用 Read 会被截断。
   先落地成纯文本再读（**必须逐页落地，逐页读完**）：

   ```bash
   cd /d/InvestSigh/InvestSigh-Read && node -e "
   const fs=require('fs');const id='<材料 id>';
   const p=JSON.parse(fs.readFileSync('corpus/materials/'+id+'/pages.json','utf8'));
   p.pages.forEach(g=>fs.writeFileSync('/tmp/'+id.slice(-12)+'_p'+g.n+'.txt',g.text,'utf8'));
   console.log(p.pages.map(g=>g.n+':'+g.text.length).join(' '));
   "
   ```

   然后用 Read 逐个读 `/tmp/*_pN.txt`。**读完全部页**才动笔；只读第一页就写答案 = 不合格。
   （页数见 frontmatter `source_pages`；长的件可达 24,000 字符/页，也要读完，可分两段 Read：`offset`/`limit`。）

1. **通读 `pages.json` 的每一页每一段**。一页的 `text` 可能包含整份文件（含多个内部页眉页脚、多张表），必须从头读到尾。
   读完在脑子里过一遍：这份是 8-K 本体、业绩附件 EX-99.1、还是和解协议/通知这类附件？
2. **枚举 Item**：全文找出所有 `Item x.xx`。注意本批原文里有 HTML 实体写法 `Item&#8201;8.01`（`&#8201;` 是窄空格），
   用 `/Item[^\d]{0,12}\d\.\d\d/` 正则找，**不要**用 `Item 8.01` 字面搜（搜不到会误判"没有该条目"）。
3. **认附件**：Item 9.01 的 exhibit 清单逐条读；清单里点到、但正文没展开的（合同、律师意见、同意函），
   写「附件未在手」，**不要**按"应该有"报缺口。
4. 图：本批 `figures/` 里只有一张 Meta 的 logo 图（16KB，无信息量），**不必看图**；若你在 `content.md` 里看到别的图（表格截图、走势图），必须看图并说明。

## 2. 八问怎么答（每问的读法与缺答写法）

| 题 | 要拿到什么 | 材料没有时怎么写 |
|---|---|---|
| Q1 指引 | **区间 + 基数/假设 + 期间**三件齐。指引在业绩稿的展望段（常标 "CFO Outlook Commentary" 或 "Business Outlook"）：抄上下限、对应财季、GAAP 还是 non-GAAP、汇率影响是顺风还是逆风、几个百分点、基于什么汇率 | 「材料未给出此项」+ 说明本件只有哪些 Item / 没有展望段；**只给区间未给假设要单独点出**，不得自行外推增速 |
| Q2 非 GAAP 桥 | 逐项抄：股份支付、并购摊销、重组、税影响各多少、调整后税率；以及这些调整项**在哪些期间反复出现**（判常态化用"两年内合理可能再现"这条法定口径） | 只有口径没有对账表 → 写「未给对账表」，该口径不得采信；前瞻性 non-GAAP 允许不给对账，要单独标出 |
| Q3 量价 | 展示量（ad impressions）同比、单位价格（average price per ad）同比、用户口径（DAP/MAU 数值与同比）。**两条都要给数** | 稿内没有量价拆分就写「稿内无量价拆分」，并说明只给了合计；**禁止**用总收入增速反推量价 |
| Q4 分部 | FoA / Reality Labs 的收入与经营利润（本期与上年同期），注明是补充材料、未经审计；核对利润里含不含分摊；本期改过口径的写「口径变更、同比不可比」 | 「未按分部拆」+ 说明查了哪张表 |
| Q5 资本开支 | 当期数（现金流量表投资段 "Purchases of property and equipment" 是现金购置数；业绩稿口径常写 "including principal payments on finance leases"）+ 指引区间 + 口径（含不含融资租赁/在建工程/土地） | 「未给指引」或「材料未给出此项」；两个口径不能混着比，要分开写 |
| Q6 回购与股息 | 三样分开记：授权总额、本期已回购金额、剩余额度；股息另记每股金额与宣告日、支付总额。看现金流量表筹资段（"Repurchases of Class A common stock" / "Payments for dividends"），与业绩稿正文的措辞对照 | 「本季回购为 0」**也是答案**；没有授权额度就写材料未给出额度，只给当期支出 |
| Q7 其他条目 | 除 2.02 外逐条看 Item 1.01/1.02/1.05/2.01/2.03/2.05/2.06/3.01/4.01/4.02/5.02/5.07/7.01/8.01/9.01：每条只取**金额、期限、生效日、附件名、当事人**。没有的条目要写「本件未含该条目」 | 逐条回执，不要只写「仅 2.02」四个字——要列清本件实际有哪些 Item |
| Q8 是否法定申报 | 看稿末有没有「shall not be deemed "filed"」「furnished」这类 Section 18 免责句，以及 Item 9.01 对附件的标注：2.02、7.01 及其附件默认 furnished；只有 9.01 点名 filed 的才算正式申报文本 | 没有免责句 = 本件按正式申报处理；也要写清你对它的引用措辞该多重 |

**当材料本身不是业绩稿**（董事变动 5.02、投票结果 5.07、发债/和解 8.01、股权重组 1.01）：Q1–Q6 一律写「材料未给出此项」，并**说清本件只有哪些条目**；不要把别处的业绩数字搬进来，也不要为凑答案编"未披露"以外的推断。

## 3. 答案正文的硬要求（不合格就是白干）

1. **正文不写页码**：不写「第 N 页」，不写 `[p.1]`，不写 `（见 p.1）`。页码只出现在依据区。
2. **三层粒度**：① 结论 → ② 具体内容（谁 · 何时 · 什么 · 多少 · 什么口径）→ ③ 判断（这意味着什么 / 为什么这么判）。
   只写「有」「无」「未见。」三个字 = 不合格。
3. **数字必带四出门**：量名、数值、期间、口径，后面跟一句「所以什么」。原文写 `$51,242` 就写 512.42 亿美元并注明"百万美元口径、GAAP、2025Q3"。
4. **「未见」三段式**：未见 + 查了哪里（哪一节/哪张表/哪一页没有）+ 为何相近的那句不能算本项。**未见 ≠ 无**：
   「无」是材料明确否认，「未见」是我没找到，混起来等于给材料栽赃。
5. **不编**：材料没写的一律「材料未给出此项」；不许用行业常识补，不许说"一般来说"，不许拿别期/别份材料的数字填空。
6. **GAAP 与 non-GAAP 不混算**；一次性和经常性不混；口径变了要写「同比不可比」。
7. **$0.000006 票面值、001-35551 档案号、20-1665019 税号这类不是量价/金额证据**，不能拿来充数（Q7 若要提，只能作为"非金额事实"一句带过）。
8. **讲人话**：一句一个意思，术语首现给一句解释（DAP = 家族日活用户；FoA = 家族应用；RL = 元宇宙实验室）。
   不写「我已仔细核对」「经逐项检查」这类自述——查证体现在引用里。
9. 一格只讲一件事；答案长度以把三层说完为准（一般 150–500 字，Q7 可更长）。

## 4. 依据区怎么写（校验器只认这一种格式）

```
### 依据
- p.1｜Meta Reports Third Quarter 2025 Results
- p.1｜Revenue $ 51,242 $ 40,589 26 %
```

- 一行一条：`- p.N｜原文片段`，`N` = `pages.json` 里的 `n`（逻辑块号，1 起）。
- **逐字**：从该页 `text` 里**原样复制**，不改字、不概括、不加省略号、不换语序、不补标点。
- **实体码原样保留**：`&#160;`、`&#8201;`、`&#8220;`、`&#167;`、`&#9744;` 这些照抄；
  `\$725` 这类反斜杠也照抄。改一个字符就会判"查无此文"。
- **数字被拆行是正常的**：原文常把 `$` 与 `51,242` 分成两行。校验不认空白，你可以写成 `Revenue $ 51,242`（一行内用空格连起来）。
- **有几处支撑就登几处**，不同页分开登；**每条有答案的行至少 1 块**（这是校验器唯一会卡的规则）。
- 引用长度：一条一般 1–3 句，能定位到事实即可；**表格行抄完整一行**，别抄半行。
- 引文里的引号用原文的（含 `&#8220;` 或 `"`），不要自己改成中文引号。

**"材料未给出此项"的行也必须登依据**：登那条能证明本件范围的原句（Item 索引行、9.01 附件清单行、封面 `FORM 8-K` 行），
用它支撑「本件只有这些条目、没有业绩稿/没有指引段」这个判断。

**反填充（实测踩过）**：
- 缺答行**只登 1–2 条**范围证据，不要把同一张附件长表（六档票据那类）在 Q1–Q6 里反复粘六遍。
- 同一段引文**不要在多题重复**；确需同一句支撑两题时，最多出现两次，且两题的用法要不同。
- 依据是"支撑这一条答案"，不是"证明我很努力"。长表只在真正用到它的那一题登（通常是 Q7）。

## 5. 自检（必须做到绿）

```bash
cd /d/InvestSigh/InvestSigh-Read && node server/check.mjs meta/<材料 id>
```

- 输出 `OK` 才算完；出现 `unverified`（查无此文）说明抄错字或抄了别的页，回原文重抄；
  出现 `no-block` 说明某行有答案没登依据；出现 `out-of-range` 说明 `p.N` 超页数（本批最大页数见 frontmatter 的 `source_pages`）。
- 不信第一次就绿：**填完再跑一次**，绿了再交。

1. 这份是什么（一句话）+ 本件实际包含的 Item 清单；
2. 八问各一句结论（有数就给数）；
3. 覆盖情况：每页读到什么、哪些段落判为免责/程序样板而略过、`content.md` 里有没有图；
4. `check.mjs` 的输出原文（那一行 OK）；
5. 红灯（手册 §6：审计师变更、重述、减值、网络安全、退出成本、"一次性"常年出现、指引撤回、回购口径冲突、协议事实挂不上格）——命中的写清哪一段、多少、与什么比；没命中就写"无"。
