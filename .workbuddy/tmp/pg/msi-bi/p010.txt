The advantage of this approach is that each token is guaranteed to be attended to by K experts, making sure the information value of each token is absorbed by the same number experts. The disadvantage is that certain experts can be disproportionately ‘popular’ with tokens while other experts are under-trained, resulting in an imbalance in the ‘intelligence’ of each expert. A known problem, many of the top labs have developed a fix with auxiliary-loss (or loss-less) load balancing. When training with EP (Expert Parallelism), this can lead to lower training MFU, as the model is spread across different GPU nodes, resulting in many more collectives (NCCL) running across the scale-out network (InfiniBand or RoCE) instead of the scale-up network (NVLink). This is a major motivation for NVIDIA’s NVL72 design, where the scaleup network expands beyond standard 8-way servers.
这种做法的优点是，每个 token 都能保证被 K 个专家处理，从而确保每个 token 的信息价值都被相同数量的专家吸收。缺点则是，某些专家可能对 token 格外“受欢迎”，而另一些专家训练不足，导致各个专家的“智能”水平失衡。这是一个已知问题，许多顶尖实验室已用辅助损失（或无损失）的负载均衡方法加以修正。在使用 EP（Expert Parallelism，专家并行）训练时，这会拉低训练 MFU（模型 FLOP 利用率），因为模型被摊到不同的 GPU 节点上，导致大量集合通信（NCCL）不得不跑在横向扩展网络（InfiniBand 或 RoCE）而非纵向扩展网络（NVLink）上。这正是英伟达 NVL72 设计的主要动因之一— 它把纵向扩展网络从标准的 8 路服务器进一步扩大。
Expert choice routing, introduced by Google in 2022, flips the logic: experts choose the top-N tokens. Taking the same T x E tensor produced by the router, in expert choice routing a topN softmax is run on the T dimension which produces a E by N tensor. This effectively means each of the E experts has chosen the N highest probability tokens to be routed. The N hyperparameter can be tuned by the researcher but to compare it to a token choice routing approach, N = K \* T / E.
由 Google 于 2022 年提出的专家选择路由（expert choice routing）则反转了这一逻辑：由专家来挑选 top-N个 token。同样取路由器产出的那个 T × E 张量，在专家选择路由中会在 T 维上执行 topN softmax，得到一个 E × N 的张量。这实际上意味着，E 个专家中的每一个都挑选了 N 个概率最高的 token 来分派。N 这个超参数可由研究者调节；若与 token 选择路由作对比，则 N = K × T / E。

When compared directly to token choice routing, expert choice routing guarantees that experts are being activated in a balanced manner, avoiding the performance degradations associated with imbalanced experts. To be clear: the router makes the choice in both cases. In token choice, the input to the router is the tokens, and it picks the experts. In expert choice, the input to the router is the experts, and it picks the tokens.
与 token 选择路由直接对比，专家选择路由能保证各专家被均衡地激活，从而避免因专家失衡而带来的性能下降。需要说明的是：两种情形下都是由路由器做选择。在 token 选择中，路由器的输入是 token，由它来挑专家；在专家选择中，路由器的输入是专家，由它来挑 token。
